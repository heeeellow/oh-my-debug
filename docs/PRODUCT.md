# TestTools 产品设计

[返回项目首页](../README.md)

## 1. 产品定位

TestTools 是面向 Rockchip 板卡与通用硬件研发、测试和现场排障的轻量级 Windows 调试工作台。产品围绕串口调试（单串口、双端链路、Debug 串口终端）、ADB 调试（文件传输、投屏控制）和设备连接诊断组织工作流，不把底层协议字段或设备侧内部实现直接暴露给普通使用者。

首版优先保证高频任务完整、结果可信和异常可恢复。当前实现与验证范围以 [`STATUS.md`](STATUS.md) 为准，具体行为由对应的 `features/` 功能契约定义，后续候选方案见 [ADR-0005](decisions/0005-adb-workspace-terminal-and-files.md)。

## 2. 使用者与主要任务

- 板卡软件工程师：连接本地或设备串口，观察收发并定位通信问题。
- 测试工程师：连接串口，复用常用指令并记录调试结果。
- 现场支持人员：确认设备状态，完成安全的串口诊断。
- 板卡调试人员：拉取日志、手动上传文件，或投屏操作 Android 界面并保存截图。

界面依次回答四个问题：

1. 当前操作的是哪台设备，是否已准备好？
2. 现在要调试串口、传输文件，还是操作设备画面？
3. 当前任务进行到哪里，能否停止或重试？
4. 收发结果是什么，下一步做什么？

## 3. 信息架构

```text
全局设备栏
├── 当前设备
├── ADB 连接状态
├── 调试服务状态与连接入口
└── 刷新设备

主导航
├── 串口调试
│   ├── 单串口调试（启动默认页）
│   ├── 双端调试
│   └── 串口终端
├── ADB 调试
│   ├── 文件传输
│   └── 远程调试
└── 设备信息
```

- 启动后直接进入串口调试，承载单串口、双端链路和可靠性工具，避免多余的概览跳转步骤。
- 串口与 ADB 使用同一种左侧二级导航：父级文字恢复本次运行中上次使用的子页并展开；首次分别进入单串口与文件传输。父级与当前子页同时选中，父级表示功能组、子级表示具体页面；独立箭头只收起/展开导航，不切页或停止任务；内容区不重复提供模式页签。串口模式切换仍受活动任务与端点占用限制，拒绝切换时保留原页面和选中项。
- 设备信息展示型号、系统、硬件资源、Agent 就绪状态、可用功能和连接维护动作。

设备选择只确定操作对象，不暗中修改串口参数。

ADB 的“远程调试”集中提供系统终端与 Android 投屏入口，两者均使用当前选择的在线设备，无需连接调试服务。
进入页面不自动启动窗口，两种会话各自固定启动设备；文件页不保留终端快捷入口。行为见
[ADB 终端契约](features/ADB_TERMINAL.md) 和 [投屏契约](features/SCREEN_MIRROR.md)。

顶栏分别显示当前设备的 ADB 连接状态与调试服务状态；具体串口打开状态留在端点旁。
板端串口依赖服务就绪，本地串口、文件传输、终端与投屏不因服务未连接而被统一禁用。

## 4. 核心任务规则

### ADB 文件传输

在独立双栏页面打开本地和设备目录，选择文件或文件夹后手动上传/下载；本地初始目录使用实际桌面。
设备目录可以从现有终端 `pwd` 后复制粘贴，不要求自动同步终端目录。用户自行在本地编辑，需要时重新选择文件上传；
不维护待写回状态或编辑器监听。任务、冲突、权限和取消边界见 [文件传输契约](features/FILE_TRANSFER.md)。

### 串口调试

- 默认进入单串口调试；双端链路与可靠性测试放在高级方式中。
- Debug 串口控制台使用独立“串口终端”页面，会话、参数和显示缓冲与单/双串口调试分开；切页保留各自连接，同一串口互斥。支持直接键盘交互和连续输出解析；
  行为与兼容范围见 [串口终端契约](features/SERIAL_TERMINAL.md)。
- 单串口模式提供本地快捷指令库（支持 AT/文本指令与 HEX 指令），支持一键填入发送框或直接发送，
  文本快捷指令与手动发送共用发送数据区唯一的行尾选择。
- 选择指令不会自动发送；快捷发送复用当前串口会话、发送队列、TX 记录和错误处理。
- 支持收发计数一键清零、自动滚动开关、日志一键导出、RX 接收批次独立记录与 TX/RX 颜色区分，以及
  串口常用参数本地自动记忆。
- 文本、HEX、行尾和计划发送均由使用者明确选择，端口名称不改变发送语义。
- 空闲时自动发现设备插拔并保留当前选择；列表变化不得自动切换到另一台设备，手动刷新仍作为恢复入口。
- 普通计划发送与可靠性测试使用独立参数、状态和结果。
- 数据显示不得改变原始收发字节。完整规则见 [`features/SERIAL.md`](features/SERIAL.md)。
- 接收日志支持按需搜索/过滤，快捷指令支持 JSON 共享；本地控制线仅通过明确操作改变，不随偏好自动恢复。

## 5. 产品用语

用户界面使用任务语言，不展示内部组件名、连接协议名、数据字段名或开发验证入口。

| 使用 | 不使用 |
| --- | --- |
| 设备、连接设备、设备信息 | 内部连接工具或服务名称 |
| 串口调试、快捷指令 | 框架、执行器、数据来源分类 |

技术标识只允许出现在开发文档或明确进入的高级诊断信息中，不能成为完成普通任务的前置知识。

## 6. 首版范围

| 范围 | 首版要求 |
| --- | --- |
| 设备选择与准备 | 清楚显示设备、连接和可用功能；失败给出可执行下一步 |
| 串口调试 | 单端主流程完整；支持本地 AT/HEX 快捷指令库與配置记忆；双端验证与可靠性工具保持独立 |
| ADB 调试 | 文件/文件夹手动收发；系统终端动作；独立投屏画面、常用控制与截图。内置终端与自动目录联动后置 |

首版不做多板并发、任意远程命令、动态插件、流程图编排、云平台和复杂权限系统。尚未验证的功能
不得用可点击占位入口呈现。

## 7. 交付原则

- 功能框架完成、具体能力验证通过、可交给测试人员使用是三个独立条件。
- 本地构建通过不等于设备验证通过；历史设备结果不自动代表当前工作树。
- 行为变化同步更新唯一功能契约和 [`STATUS.md`](STATUS.md)，不复制多份当前状态。
