# TestTools 产品设计基线

[返回项目首页](../README.md)

## 1. 产品定位

TestTools 是面向 Rockchip 板卡研发、测试和现场支持的 Windows 调试与测试工作台。它把设备选择、
板端能力、交互式调试、自动化测试、结果证据和运行记录组织为一致流程，而不是把 ADB 命令和独立
小工具简单堆叠在一个窗口中。

当前产品首先保证串口调试可用，并通过无 Qt 的板端 Agent 逐步接入 DDR、存储、音频、网络、GPIO、
重启和休眠等能力。当前实现范围和开放项以 [`STATUS.md`](STATUS.md) 为准。

## 2. 使用者与主要任务

- 板卡软件工程师：快速选择目标设备，打开本地或板端串口，观察 TX/RX 并定位通信问题。
- 测试工程师：复用确定参数，执行按次数发送、可靠性测试和后续板级测试，获得可比较结果。
- 现场支持人员：确认设备、Agent 和能力状态，以较少配置完成安全检查并导出证据。

界面应帮助使用者依次回答：

1. 当前操作的是哪块设备，连接是否健康？
2. 我现在要调试一个串口，还是调试两端链路并按需执行验证或压测？
3. 当前任务处于什么状态，哪些操作仍然可用？
4. 失败发生在哪个阶段，直接证据和安全的下一步是什么？

## 3. 产品信息架构

```text
全局设备上下文
├── 当前设备
├── ADB 状态
├── Agent 状态、版本与能力
└── 刷新、连接和部署入口

功能导航
├── 概览
├── 串口工作台
├── 测试中心
├── 运行记录
└── 设置

任务反馈
├── 当前状态和进度
├── 结构化结果
├── 可展开证据
└── 恢复、重试或取消动作
```

全局设备选择只决定操作对象，不替代页面内的任务选择。设置页负责连接和应用配置，不承载具体
测试参数。

## 4. 串口工作台的任务模型

串口页按连接拓扑提供两个显式调试方式：

- 单串口调试：默认入口。连接一个串口，在统一终端中查看 TX/RX，手动或按计划发送数据。
- 双端调试：配置端点 A/B，观察两端数据，并按需执行双向收发验证或可靠性压测。

方式切换改变页面结构，但不暗中修改串口参数。可靠性压测虽位于双端调试中，仍使用独立参数、状态
和结果，不能与普通定时/次数发送耦合。详细行为见 [`features/SERIAL.md`](features/SERIAL.md)。

## 5. 产品术语

| 术语 | 含义 | 不应混用 |
| --- | --- | --- |
| 设备 | 顶栏当前选中的物理板卡 | 串口端点 |
| Agent | 运行在板端、提供受控能力的服务 | ADB、任意远程 shell |
| 串口端点 | 一个 Windows COM 或板端 `/dev/tty*` 数据通道 | 整块设备 |
| TX / 已发送 | TestTools 已写入传输层的数据 | 外设自身回显 |
| RX / 已接收 | TestTools 从传输层收到的数据 | 本地发送记录 |
| 定时/次数发送 | 按用户内容和间隔重复发送 | 可靠性压测 |
| 可靠性压测 | 使用带序号和校验的测试帧统计链路质量 | 普通命令自动发送 |
| 行尾 | 用户显式追加的 LF、CR 或 CRLF 字节 | 根据端口名称推断的协议 |

## 6. 产品规则

- 默认路径优先服务最常见任务，复杂能力通过模式或扩展面板进入。
- 自动发现可以提供建议，但不能把推断当作用户意图；任何自动选择都必须可见、可撤销。
- 一个操作区只保留一个主动作；状态变化后按钮文案和可用性必须与当前状态一致。
- 错误信息说明失败阶段、对象、原因和可执行下一步，不直接展示无法理解的原始错误码。
- 运行记录以一次任务为单位保存设备快照、参数、结果和产物，不以零散日志行作为主索引。
- 未实现能力显示进入条件和实现状态，不提供看似可点击但无响应的控制。
- 破坏性或长时间任务在开始前显示影响、持续时间、资源占用和取消能力。

## 7. 当前非目标

- 不提供任意 shell 命令执行界面。
- 不在第一阶段提供可自由拖拽和保存的复杂工作区布局。
- 不把所有能力强行生成为通用参数表单；波形、图像和串口等复杂能力使用专用界面。
- 不依赖某一种设计工具、AI 工具或外部知识库才能理解和维护项目。
