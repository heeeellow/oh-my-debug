## GPIO 占用差异的实测原因

MTB-720（RK3568、4.19.193+）使用原 0.3.10 服务时，`gpio.chip.list` 的六组控制器均报
`GPIO v2 line info: Invalid argument`，没有枚举出占用行。旧实现只把 ENOTTY 当成 v2 不支持，
遗漏该固件的 EINVAL 返回。修复后由 v1 只读查询验证兼容，其他错误尤其权限拒绝不降级。

新版本按实际 Linux 全局号对照同一台设备的 `debug/gpio`：161 行完整枚举，
33 个已占用行和 consumer 全部匹配。RK3562 / 5.10 上的 v2 145 行只读回归也通过。
这些是当前两块板的实际结果，不推定所有厂商固件都返回相同 errno。

GPIO 信息来自 [v1 行信息接口](https://docs.kernel.org/userspace-api/gpio/gpio-get-lineinfo-ioctl.html)
或 [v2 行信息接口](https://docs.kernel.org/userspace-api/gpio/gpio-v2-get-lineinfo-ioctl.html)，
枚举不申请电平句柄。列表为时间点快照，新增可见页 3 秒后台刷新与结束补查；申请时仍由内核裁决。
空 consumer 不等于未占用，界面保留明确的占用标记。

## 编号与收藏

管脚计算独立于设备连接：`GPIO3_B4 = 3×32+1×8+4 = 108`，控制器内 offset 为 12。
实际 Linux 全局号使用已核对的 sysfs 基址，不能用 gpiochip 序号推断。
MTB-720 的 PMIC 就是 gpiochip5 offset 0 / gpio-511，不能写成 gpio-160。

收藏原来承担了防误操作门槛，给临时调试增加了无关步骤。本轮将收藏/备注与控制拆开：
未收藏也能操作未占用行，原目标/参数确认、占用检查、租约和释放机制保留。
夹具验证了未收藏时控制可用，取消确认不产生输出，并核对外部占用变化会自动更新。

## 网口选择与曲线

无 IP、断链或停用的物理接口现在仍在列表中且可选择，原因显示在选项和状态旁。
开始前才要求真实 IPv4、链路和正确路由；没有隐式配置 IP。软件夹具验证了无地址选择和配置后恢复同一接口。

旧曲线只读取最近一份 interval，批量输出会丢中间点；第二方向的时间回到零还会清空第一方向。
修复后每 0.5 秒采样，后台和报告保留全部点，界面按方向重建，减少 GUI 调度对采样的影响。
两条曲线、坐标、图例、点、数值、悬停与显式波动缩放分开提供；缩放不修改采样或制造波动。

真实 LAN 验证使用 192.168.1.211 ↔ 192.168.1.111，TCP 接收约 949/947 Mbps；
UDP 20 Mbps 双向零丢包。TCP 每方向 20 点，UDP 每方向 10 点，在原生界面完整保留。
确切参数、数值、报告和清理结果只汇总在 STATUS，后续环境变化需重新验证。
