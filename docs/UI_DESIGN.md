# TestTools 界面与交互设计

## 1. 使用者与核心任务

主要使用者是板卡软件工程师、测试工程师和现场支持人员。他们通常处于以下情境：

- 已连接一块或多块板卡，需要先判断当前操作对象和连接状态。
- 带着明确目标进入某个功能，例如打开 UART、执行 DDR 压测或检查存储健康度。
- 需要持续观察进度和关键输出，但不希望被完整原始日志淹没。
- 任务失败后需要知道失败阶段、直接证据和下一步，而不只是一个红色 FAIL。
- 需要复查此前使用的参数、板卡版本和产物。

因此界面按“设备 -> 功能 -> 任务 -> 证据”组织，而不是按底层命令或库组织。

## 2. 信息架构

```text
设备栏
├── 当前设备
├── ADB 状态
├── Agent 状态与版本
└── 刷新/连接

功能导航
├── 概览
├── 串口工作台
├── 测试中心
├── 运行记录
└── 设置

主工作区
├── 页面标题与一句话状态
├── 主要操作
├── 当前运行结果
└── 页面级辅助信息

活动面板
├── 当前任务
├── 结构化事件
└── 诊断日志
```

串口页面保留双端点并排，因为比较和双向验证是该功能的核心；它不再承担整个应用的设备选择和
全局状态。

## 4. 视觉方向

采用接近原生桌面工具的轻量工作台风格：

- 用相邻的中性灰区分应用背景、导航、工具栏和工作表面，不用深色顶栏制造强分割。
- 只保留一个低饱和蓝色强调色；绿色、棕黄和红色仅用于真实状态，不把普通状态做成彩色胶囊。
- 概览信息优先放在一个连续表面中，用留白和细分隔线建立关系，避免每个信息都变成独立卡片。
- 日志与接收区使用低对比浅灰表面；只有用户主动切换深色模式时才使用大面积深色控制台。
- Windows 优先使用 Segoe UI Variable Text，基础字号 13px；页面标题 20px、关键值 17px、辅助文字
  12px，字重只使用 400 和 500。
- 原始数据使用 Cascadia Mono/Consolas；动态数字使用等宽字体，正文不滥用等宽字体。
- 常规正文和辅助文字按至少 4.5:1 对比度检查；禁用态和占位符不承担关键信息。
- 圆角保持在 4–8px，不用渐变、发光、大阴影、装饰性大图标和多套强调色。
- 状态同时使用文字和颜色，不能只靠颜色区分。

## 5. 开源参考与采用边界

- [Qlementine](https://github.com/oclero/qlementine)：参考现代 `QStyle` 的控件密度、圆角、间距和
  状态处理。它是 MIT 许可并支持 Qt 6 Widgets；第一阶段不直接引入依赖。
- [Fluent-Qt](https://github.com/calvinhxx/Fluent-Qt)：参考导航、信息栏、主题和 Fluent 控件语义。
  它是 MIT 许可；项目目前较新，只作视觉与交互参考。
- [Qt Creator UI](https://doc.qt.io/qtcreator/creator-quick-tour.html)：参考稳定模式导航、目标设备选择和
  底部输出面板的信息架构。
- [Qt Advanced Docking System](https://github.com/githubuser0xFFFF/Qt-Advanced-Docking-System)：作为
  后续复杂监控页面的候选，不在第一阶段引入。其 LGPL-2.1 许可和部署义务需要在真正集成前单独评估。
- [Fluent 2](https://fluent2.microsoft.design/)：参考中性色表面层级、原生字体、语义色和一致的设计
  token；不照搬其营销型卡片布局。
- [KDE HIG](https://develop.kde.org/hig/)：参考“默认简单、需要时强大”和克制使用粗体、短而可执行的
  标签规则。
- [Libadwaita Style Classes](https://gnome.pages.gitlab.gnome.org/libadwaita/doc/main/style-classes.html)：
  参考 heading、body、caption、monospace 等清晰的文字角色，以及连续列表优先于重复卡片的做法。
- [IntelliJ Platform UI Kit](https://blog.jetbrains.com/idea/2021/05/intellij-platform-ui-kit/)：参考 Windows
  下 Segoe UI、JetBrains Mono 和面向开发工具的紧凑控件节奏。

不复制参考项目源码、品牌资源或整套主题；当前实现使用本项目自己的布局和 QSS。

## 6. 交互规则

- 全局设备切换始终可见；运行破坏性任务时禁止切换或要求先处理当前任务。
- 主页面每个操作组只有一个高强调按钮。
- 长任务开始前展示持续时间、资源占用、是否写存储或重启。
- 失败结果显示阶段、错误码、摘要和展开证据入口。
- 日志默认折叠为摘要，只有定位问题时才展开。
- 扫描、连接和测试都不能阻塞 GUI；进行中状态必须能被看见。
- 未实现功能显示进入条件和演进状态，不放置无响应按钮。

## 7. 页面策略

- 概览：设备身份、连接健康、最近任务和常用入口，不堆砌无行动价值的指标。
- 串口工作台：专用双端点页面，强调路由、收发和验证。定时 / 次数发送的间隔、次数与 TX 记录选项使用
  按需弹窗，避免长期占用监视区；可靠性压测把丢帧、格式错误和载荷 BER 分开呈现。
- 测试中心：按类别展示 Agent 返回的能力；简单测试进入通用运行页。
- 运行记录：以一次运行作为单位，包含设备快照、参数、结果和产物。
- 设置：连接、Agent 部署、日志保留和外观；不混入具体测试参数。

## 8. 验收标准

- 启动后 5 秒内能看出当前设备、连接状态和主要功能入口。
- 在设置页连接 Agent 后，进入串口页无需理解 ADB 转发即可完成连接、收发和双向验证。
- 1366x768 下主要操作不被裁切；窗口缩小后页面允许纵向滚动而不重叠。
- 键盘焦点可见，状态不只依赖颜色，正文对比度清晰。
- 页面切换不改变连接状态；退出应用能确定性关闭后台线程和串口。
