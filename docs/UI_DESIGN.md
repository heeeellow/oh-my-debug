# TestTools 界面与交互设计

[返回项目首页](../README.md)

## 1. 设计目标

界面服务于长时间调试和重复测试，应当轻量、清晰、可预测。视觉调整必须先解决任务层级和状态
表达，再处理颜色、圆角等表面风格。产品任务和术语以 [`PRODUCT.md`](PRODUCT.md) 为准，串口
细节以 [`features/SERIAL.md`](features/SERIAL.md) 为准。

设计原则：

- 先显示当前设备、当前任务和下一步动作，低频参数按需展开。
- 一个操作区只有一个主按钮，颜色只表达动作层级和真实状态。
- 自动发现只提供可见建议，不能根据端口名称暗中改变用户输入或协议。
- 相同状态在不同页面使用相同文案、颜色和按钮行为。
- 失败首先给出阶段、对象和可执行下一步，原始日志作为证据展开。
- 默认布局固定且可复现；没有真实多视图需求时不引入 Docking。

## 2. 整体布局

```text
┌─────────────────────────────────────────────────────────────────────┐
│ TestTools   当前设备 [设备 ▼]   ADB 状态   Agent 状态   刷新/Agent 管理 │
├──────────────┬──────────────────────────────────────────────────────┤
│ 概览         │ 页面标题、简短说明和页面级主要动作                   │
│ 串口工作台   │                                                      │
│ 测试中心     │ 当前模式的主要工作区                                 │
│ 运行记录     │                                                      │
│ 设置         │                                                      │
├──────────────┴──────────────────────────────────────────────────────┤
│ 当前任务或最近活动摘要                                  展开证据    │
└─────────────────────────────────────────────────────────────────────┘
```

- 顶栏只保存全局设备上下文，不放具体测试参数。
- 左侧导航保持稳定，当前项同时用背景、文字和窄边标识。
- 页面标题下只放一句说明；常驻帮助文字不能代替清晰控件名称。
- 底部活动区默认是一行摘要，有任务或错误时可展开，不长期挤压主工作区。

## 3. 串口页面结构

页面顶部使用分段选择或同等清晰的控件切换任务模式：

```text
[单串口调试] [双端调试]
```

默认单串口调试：

```text
连接栏  [来源] [端口] [波特率] [更多参数]                    [连接]
状态栏  当前端点、连接状态、请求/有效参数和字节计数
终端区  按时间顺序显示 TX / RX / 状态，可筛选 HEX 与时间戳
发送栏  [输入要发送的数据                         ] [行尾] [发送]
         [文本/HEX] [行尾] [定时/次数发送…]
```

双端调试才显示端点 A/B 和链路级动作；双向收发验证与可靠性压测作为该方式下的按需子功能。
压测复用两端连接，但参数、运行状态和结果不与普通定时/次数发送混用。方式切换和状态保留规则见
串口功能契约。

## 4. 文字系统

字体优先级：

```text
界面：Segoe UI Variable Text, Segoe UI, Microsoft YaHei UI
数据：Cascadia Mono, Consolas, Microsoft YaHei UI
```

| 角色 | 建议字号 | 字重 | 用途 |
| --- | --- | --- | --- |
| 页面标题 | 22px | 500/600 | 当前页面名称 |
| 区域标题 | 16px | 500 | 终端、连接、结果等区域 |
| 正文与控件 | 14px | 400 | 标签、输入和按钮 |
| 辅助文字 | 12px | 400 | 非关键说明、时间和计数 |
| 终端数据 | 13px | 400 | TX/RX 和原始数据 |

正文和关键标签不能依赖占位符传达。中英文混排避免用过细字重；Windows 100%、125% 和 150% DPI
下均以逻辑字号和实际截图检查清晰度。

## 5. 颜色与表面

第一阶段只提供浅色主题，使用少量固定语义 token：

| Token | 建议值 | 用途 |
| --- | --- | --- |
| `surface.app` | `#F6F7F9` | 应用背景 |
| `surface.panel` | `#FFFFFF` | 工作表面、输入和弹窗 |
| `surface.subtle` | `#F1F3F5` | 终端、悬停和次级分组 |
| `border.subtle` | `#DCE1E6` | 非交互分隔线和连续表面边界 |
| `border.control` | `#89939E` | 白色控件表面上的输入、选择和按钮边界 |
| `text.primary` | `#20242A` | 标题、正文、输入值 |
| `text.secondary` | `#4F5964` | 次要标签和说明 |
| `text.muted` | `#626D78` | 非关键元数据，不承载唯一信息 |
| `accent.default` | `#356A9A` | 当前选择和主动作 |
| `accent.hover` | `#2E5F8A` | 主动作悬停 |
| `status.success` | `#24705A` | 已连接、成功 |
| `status.warning` | `#805A18` | 风险、等待、降级 |
| `status.error` | `#AD3B32` | 失败、危险动作 |

实现时必须按实际背景计算对比度：常规文字至少 4.5:1，大号文字和必要控件边界至少 3:1。低对比
`border.subtle` 只能用于不承担识别职责的分隔线；输入和按钮使用 `border.control`、背景差异或其他
达到 3:1 的可见边界。禁用态可以降低强调，但仍应能辨认控件名称；占位符不承担关键指令。

大面积区域用背景和留白分层，避免重复卡片、粗边框、渐变、发光和装饰性阴影。圆角统一为 6–8px，
不能通过不断增加圆角制造“现代感”。

## 6. 间距与控件

间距基于 `4 / 8 / 12 / 16 / 24 / 32px`。常规控件建议高度 34–36px，紧凑工具按钮最低 32px。
同组字段间距小于不同区域间距；标签和控件左边缘对齐。

按钮层级：

- 主按钮：实心强调色，一个操作区最多一个，例如“连接”“发送”“开始测试”。
- 次要按钮：白色表面和清晰边框，例如“更多参数”“导出”。
- 文字按钮：低风险辅助动作，例如“清空显示”“查看证据”。
- 危险按钮：仅用于停止、强制中断等真实风险动作，并配合明确文案。

按钮不能只写“确定”“管理”等缺少对象的文字。进行中动作使用“正在连接…”等状态，但不得用永久
禁用让用户无法理解发生了什么。

## 7. 状态、文案与反馈

- 连接状态固定使用“未连接、正在连接、已连接、正在断开、连接失败、正在重连”。
- TX、RX、错误和状态同时用文字/符号与颜色区分，不能只依赖红绿。
- 成功反馈应克制；失败反馈保留在当前任务上下文中，直到用户处理或明确关闭。
- 通用发送区使用“输入要发送的数据”和“无、LF、CR、CRLF”；协议工具使用各自的文案和交互。
- 发送区明确提示 Enter 发送、Shift+Enter 换行；按钮和快捷键走同一条校验与发送路径。
- 中文文案优先短句，缩写第一次出现时提供完整含义或可访问帮助。

## 8. 可访问性与窗口适配

- 所有交互控件必须有可见键盘焦点，Tab 顺序符合视觉顺序。
- 状态、错误和方向不只靠颜色；图标如无文字必须有工具提示和可访问名称。
- 点击目标不小于 32×32 逻辑像素，关键动作建议 36px 高。
- 1366x768 不裁切连接、终端和发送主流程；低频区域允许纵向滚动。
- 1920x1080 优先把额外空间分配给终端和结果；发送区可以随工作区增长，但不能让主要动作远离输入或
  形成难以扫读的空洞布局。
- 100%、125%、150% DPI 均检查文字截断、组合框箭头、焦点边框和终端行高。

## 9. 参考边界

视觉和交互可以参考 Qlementine、Fluent 2、Qt Creator、KDE HIG、Libadwaita 和 IntelliJ Platform UI
Kit 的控件密度、信息层级和专业工具布局，但不复制其品牌资源或整套主题。直接引入开源 UI 库前
必须重新核对维护状态、Qt 版本兼容性、许可证、二进制体积和现有 QSS 迁移成本。

Figma 只用于需要多人协作的视觉方案比较、原型演示和尺寸标注，不是项目运行或构建依赖。单人快速
迭代阶段优先使用本文件、结构稿和真实 Qt 快照；出现外部设计师参与、多个方案需要评审或复杂交互
需要在编码前验证时，再建立 Figma 原型。

## 10. 界面验收

- 启动后 5 秒内能识别当前设备、ADB/Agent 状态和主要功能入口。
- 普通串口用户无需理解双端链路即可完成连接、发送和查看 TX/RX。
- 每个页面的主动作唯一，未实现能力没有伪按钮。
- 文本、HEX、四种行尾、计划发送和异常断开状态与功能契约一致。
- 目标分辨率和 DPI 无关键裁切，键盘可完成主要流程，焦点始终可见。
- 页面切换不意外断开会话；退出能确定性关闭后台线程和设备资源。
