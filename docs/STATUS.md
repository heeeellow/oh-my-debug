## 2. 当前实现

### 串口与终端

- 单/双串口页由 `SerialWorkspace` 负责，独立终端由 `SerialTerminalWorkspace` 负责且仅创建一个实际端点；两者通过 `SerialEndpointWorkspace` 共用连接、代次、端口登记、显示投递、录制与关闭规则。终端不再创建普通发送、快捷指令或双端测试控件；既有解析器、按键字节、偏好文件和切页行为保持。
- 快捷指令管理弹窗提取为独立组件；双端验证与压测的帧、方向、线速间隔、接收和结果状态由无 Qt 的 `SerialLinkVerifier` 管理，普通计划发送仍归 `SerialSession`。GUI 只负责动作、展示与已有超时回调；发送调度使用 `Qt::PreciseTimer` 且仅在计划发送或压测仍需提交数据时运行，等待压测尾部数据时停止空转。
- 单/双串口调试继续支持 PC端串口（Windows COM）、设备串口、文本/HEX、共享普通行尾、独立计划发送及双端验证/可靠性压测。规则见 [串口契约](features/SERIAL.md)。
- PC端串口刷新只更新主机列表，不请求设备串口，不受服务状态、设备扫描或维护影响；当前活动端点自身仍锁定，空闲端点可在另一端活动时刷新，保留手工端口草稿。单/双串口与终端统一使用“PC端串口”来源名。
- 单串口右侧提供独立快捷指令侧栏，逐项填入/发送、预览与指令库菜单。选择不发送；文本指令复用共享行尾，HEX 发送原始字节。侧栏宽度和展开偏好独立于窗口自动适配保存，窄屏可自动收起并恢复。
- 单串口和终端去除重复外层端点卡片，双端保留 A/B 分组。串口未连接时突出连接动作，连接后断开转为次级；普通发送仍使用主按钮。
- 普通接收区的保存/清零位于“更多”，空间不足时显示开关也进入菜单。终端保留直接输入、搜索、保存、清屏和终端选项，无底部命令框或快捷侧栏。
- 终端仍为独立页面和会话，使用 `terminal-preferences.json`，切页保留连接，同口登记与异步释放保持。连续 UTF-8/ANSI 与 10000 行/1M 字符单元的回看边界见 [终端契约](features/SERIAL_TERMINAL.md)。
- 新增会话级后台持续录制：带 RX/TX 与采集时间的文本、原始 RX 二进制及 JSON 元数据；独立于显示清屏、过滤和裁剪。停止、断线与退出排空已接受数据，失败保留文件和原因，不关闭串口。
- 接收显示队列与录制队列分别有字节和批次数上限；显示淘汰旧数据时提示缺口，受影响的双向验证/压测停止。原始 RX 录制在显示队列之前。
- 标题栏高亮按固定词增量叠加错误/警告样式，搜索优先；关闭后恢复原 ANSI，偏好按通道保存，原始缓冲和文本导出不变。

### 全局设备与服务

- 顶栏刷新紧邻设备选择，ADB 与“板端服务”使用独立的无实体边框状态标签；服务动作使用连接服务、服务详情、重试连接；在线可连接时突出主动作，后台现有服务探测不占用显式连接入口，显式准备中显示实际步骤。
- 每个串口端点在连接动作位置内联显示服务未就绪原因和连接/重试入口，保留日志区域高度。本地 COM 与 ADB/服务状态独立，活动设备串口保留维护保护。
- 左侧父级导航文字与展开箭头共享圆角背景，使用内置线性箭头；父级/子页选中、折叠与上次子页规则保持。底部活动消息附本地时间戳，右侧按快照汇总录制、计划发送、压测与传输，并提供各自停止入口；无活动任务时隐藏入口，旧任务动作不能操作新任务。
- 设备发现前台每 2.5 秒、后台每 10 秒静默进行，回到前台补查；不重建相同列表、不覆盖下拉选择，发现失败保留当前选择，其他设备变化不重复刷新当前上下文或探测服务。本地 COM 和静默扫描不禁用顶栏。Agent 健康仍每 3 秒独立检查，连续两次失败才置为失联；旧代次失效与转发清理保持，固定 Bundle v2 仍为三个目标。

### 文件与远程调试

- 文件页默认收起空任务区，首次文件任务展开；条目摘要、实际目标和主动作同排，长路径省略并保留完整提示。列表右键集中管理操作，标题栏不再重复放置“操作”下拉；收藏直接并入设备地址栏，分组下拉跨组去重。
- 设备地址按收藏、常用和最近访问分组，按设备保留最近目录与收藏；Android / Rockchip Linux 的预置随目录读取的系统提示更新；Android 增加 `/sdcard/oem_log`，移除默认 `/tmp`。支持批量格式的设备使用固定 `find` 查询读取属性和链接类型，避免逐项启动命令；不缓存目录内容，打开失败保留原列表且不加入历史。
- 新增本地与设备新建文件夹、同目录重命名、直接删除；设备普通文件和文件夹可在“修改权限”弹窗中勾选权限位或输入八进制数，先后台重新读取实际值，多选不一致须明确指定，写后回读核对，仅修改所选项自身。管理与传输共用任务 ID、互斥、停止、退出和逐项结果，失败可按原目标重试。删除确认默认取消，固定对象、目录和名单，确认期间切换设备会拒绝旧操作。
- 执行层检查实际路径、类型和挂载证据，保护关键目录与挂载点；本地递归删除不进入重解析点，设备删除不跟随链接。完整规则见 [文件契约](features/FILE_TRANSFER.md)。原有传输、暂存替换保持；目录下拉复用内置文件夹图标，内部刷新屏蔽地址编辑通知，减少重复界面更新。
- 操作图标统一为用户选择的“清晰线性”：刷新、导航、上传下载、收藏、右键操作、日志保存/清空与投屏控制使用内置 SVG，支持实际 DPR 渲染及缓存；设备文件直接按类别显示，本地普通文件保留 Windows 关联图标。图标与许可固定纳入仓库，使用时不联网。样式规则见 [界面设计](UI_DESIGN.md)。
- 左侧远程调试排在文件传输前，首次点击 ADB 分组进入远程调试。ADB Shell 打开前只读核对实际 UID，沿用设备当前权限，不主动 Root 或 Unroot；Android 服务准备可能已请求 Root。Shell 与 scrcpy 投屏各自固定启动设备，均不要求板端服务；投屏保持独立窗口与 `--no-audio`。规则见 [投屏契约](features/SCREEN_MIRROR.md)。
- 远程调试页改为响应式双栏：左侧为 Shell、诊断日志和设备维护，右侧为投屏；内容宽度不足时上下排列并滚动，切换布局保留会话。
- 新增 Logcat/dmesg 流式导出到本地文件，大日志不进入 GUI 或通用输出缓冲；保存对话框处理覆盖确认，失败/超时/取消保留部分文件、路径与原因，成功才提交目标文件。
- 新增显式 Root 与 Remount、重启：确认后固定原设备和动作，分别记录身份核验、挂载、ADB 离线/上线及等待超时。与同设备活动任务互斥，维护时使旧服务代次失效；Windows COM 和本地文件管理独立工作。停止等待不撤销已发出的设备动作。
- Remount 同时返回成功和需重启提示时分别记录命令成功与待重启生效；只有准备/重启提示时不宣称成功，不自动重启。Loader 动作具有目标资格检查与结果边界；当前没有已核实的 BSP/实机目标，产品入口隐藏，不根据 Rockchip 名称猜测支持。完整行为见 [设备维护契约](features/DEVICE_MAINTENANCE.md)。

### 设备信息与只读硬件数据

- 设备信息页上方为连接与硬件/系统两张响应式卡片；服务就绪且页面可见后自动加载并入“硬件与系统”的存储与健康摘要。同会话切页保留结果，提供刷新、停止与更新时间；未连接或未声明的能力不可启动，不自动部署服务。
- 系统可见 MemTotal 仅在硬件/系统摘要显示 GiB，提示保留精确 KiB，不再重复发起内存任务；所有 eMMC/UFS 候选保留设备键、容量、型号等字段，存储详情保留 Pre-EOL、寿命字段原值和可读 I/O 计数。缺失显示未知，设备报告的 0 保持 0；不做规格比较、不推算寿命百分比。
- 复用现有任务协议，固定设备/连接代次、顺序保留各项结果，处理取消、超时、失联、响应关联错误与远端结束状态未确认。原始结果按需查看；页面和全局任务栏均按任务 ID 停止。
- 实际桌面在后台建立独立只读控制连接，避免与主窗口断开/重连共用 socket；切换设备/服务会话后旧数据不进入新会话。与同设备维护/重置互斥，退出先收尾。规则见 [硬件信息契约](features/BOARD_INFO.md)。

## 4. 开放风险与后续

- 硬件信息已有 2026-11-02 的 RK3568 Android 11、既有 0.3.7 服务下的自动只读加载验证，P0 本轮未重跑该实机流程；不同 BSP 的可用字段由 Agent 能力和 `/proc`、`/sys` 权限决定。缺少字段或读取完成都不表示设备合格；结束状态未确认时不宣称远端任务已停止。

- 维护只控制本工具拥有的任务和固定设备，无法阻止其他程序或已打开的用户 Shell 同时操作设备。Remount 成功响应不等于所有分区可写；ADB 重新上线不等于系统启动完成；ADB 离线不等于 Loader。
- 日志写入和提交中的单次文件系统调用不保证硬超时；坏盘或网络目录可能延迟取消与退出。

- 目录性能样本仅当前 RK3568 Android；缺少所需 `find -printf` 格式时回退逐项查询，其他固件与大目录的时延未验证。
- P0 按 2026-11-03 的新授权实施；此前暂缓的新增板端能力保持暂缓，下一阶段依据体验反馈确定。
- 终端兼容范围仍是启动日志与 Shell 输入/回显/历史/补全/中断；完整 TUI、备用屏幕、滚动区域和完整宽字符表仍不在范围内。
- 串口阻塞发送、短写与传输关闭边界仍需按实机场景收敛；本批已限制显示积压，没有调整驱动或传输参数。
- 单文件录制没有自动分卷、磁盘配额或断电恢复保证；flush 不等同硬件持久化。文件系统调用没有硬超时，坏盘或网络路径可能延迟保存及退出，当前以保留数据和等待所拥有线程收尾为原则。
- 偶发“不回显、回车也无输出”未复现，根因仍未确定，不能把界面调整当作已解决。
- 文件提交阶段取消与替换可能竞争，断线可能遗留本批临时目录；变化中的日志不保证一致性快照，目录合并仍未实现。
- 文件管理的路径/挂载检查不能阻止外部进程在检查后继续改动目标；远端命令在中止等待后可能已经部分生效。本地单个文件系统调用无法保证硬超时，异常磁盘或网络目录可能延迟退出。失败/停止后须刷新复核，不能宣称回滚。
- 物理拔线、重启全程启动日志、板端串口实际收发、长时间高波特率/大文件、真实 push/pull、投屏音频共存和实际中文 IME 本批均未验证。
- `MainWindow` 继续拥有全局连接界面状态与异步代次；端点公共表现与双端测试模型已分开。终端引擎性能与完整 TUI 支持仍留给 T1，不把 P0 结构整理视为已解决全部终端卡顿。
