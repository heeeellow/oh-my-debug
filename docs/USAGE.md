# 使用手册

[返回项目首页](../README.md)

## 启动

解压 Windows x64 成品包，运行 `OhMyDebug.exe`。程序可以直接使用，无需安装 Qt 或开发环境。
移动程序时请复制整个文件夹，保留配套的 DLL、`platform-tools/`、`agent-bundle/` 和 `scrcpy/` 等目录。
如果提示缺少 MSVC 运行库，安装包内的 `vc_redist.x64.exe`。

窗口顶部用于选择 **ADB 设备**；串口页面的连接栏用于选择 **COM 口或设备串口**。
只用电脑上的 COM 口时，直接进入串口页面即可。

## 串口收发

1. 接好串口设备，在 Windows 设备管理器中确认 COM 口编号。
2. 进入“串口调试 → 单串口调试”。
3. “位置”选择“PC端串口”，点击“刷新串口”，选择对应 COM 口。
4. 设置波特率，在“更多参数”中设置数据位、校验、停止位和流控。
   例如设备要求 115200、8N1、无流控，就选择波特率 115200、8 数据位、无校验、1 停止位、无流控。
5. 点击“连接”。设备输出的数据会显示在接收区。
6. 在底部输入内容，选择文本或 HEX 模式及行尾，点击“发送”。

文本模式适合 AT 等字符串命令；HEX 模式按字节发送，例如 `41 54` 对应 ASCII 字符 `AT`。
行尾按设备协议选择 CR、LF 或 CRLF。右侧快捷指令可以“填入”发送框，也可以直接“发送”。

切换页面会保留连接。如果要在另一个页面使用同一 COM 口，先断开原页面的连接。

### 定时发送与双端调试

发送区的“定时 / 次数…”可以设置发送间隔和次数，用于反复发送同一条数据。
启动前先在发送框准备好内容和行尾。

“双端调试”提供 A/B 两个串口，可同时观察收发，也可以进行双向验证和可靠性测试。
A/B 应选择不同的端口；连接板端串口时，每台板端服务可打开一个串口会话。
可靠性测试会向链路发送测试帧，适合串口互连测试，请勿在 Debug Shell 上运行。

## 串口终端

查看启动日志、操作 U-Boot 或 Linux Shell 时，进入“串口调试 → 串口终端”。
选择串口和参数后点击“连接”，再点击终端区域直接输入，输入的文字由设备回显。

| 按键 | 默认操作 |
| --- | --- |
| Enter | 发送 CR |
| Backspace | 发送 DEL |
| Ctrl+C | 有选区时复制，无选区时发送中断 |
| Ctrl+V | 粘贴，多行内容先预览 |
| Ctrl+Shift+C / Ctrl+Shift+V | 复制 / 粘贴 |
| Ctrl+Shift+F | 搜索 |

字体、字号、行距、配色和光标在“终端选项…”中调整，回车和退格也可以改为设备需要的格式。
默认开启“智能 Ctrl+C / Ctrl+V”；关闭后，使用 Ctrl+Shift+C/V 复制粘贴，Ctrl+C/V 发送对应控制字符。

工具栏的“自动高亮”用于标记错误和警告词，“搜索”用于查找输出内容。
需要保留完整的长时间输出时，建议在开始调试前开启录制。

## 保存日志

保存已有记录时，在普通收发页打开“更多”菜单，或点击终端工具栏的“保存日志…”。

抓取启动过程或长时间日志时，点击“录制…”，选择文件位置和格式：

- **带标记文本（.log）**：包含时间和收发方向，便于直接阅读。
- **原始 RX 字节（.bin）**：保留设备发来的原始数据，适合后续解析。

录制同时生成元数据文件。结束时停止录制，等待保存完成。
录制期间可以清屏或回看历史，已录制的数据会保留在文件中。

## 连接 ADB

1. 用 USB 数据线连接设备。
2. Android 设备开启 USB 调试，在设备上确认电脑的调试授权；Linux 设备需启动 adbd。
3. 点击窗口顶部“刷新”，在设备列表中选中目标设备。
4. ADB 状态显示已连接后，进入“ADB 调试”使用文件、Shell 或投屏功能。

文件管理、Shell 和投屏直接使用 ADB。操作设备上的串口、读取板卡信息时，再连接板端服务。

### 打开 Shell

进入“ADB 调试 → 远程调试”，点击“打开 ADB 终端 ↗”，会打开当前设备的独立 Shell 窗口。
切换设备后，请重新打开终端；已有窗口继续连接原设备。

### 连接板端服务

1. 选中 ADB 设备，点击顶部“连接服务”。程序会按需部署和启动匹配的服务。
2. 服务连接成功后，在串口页将“位置”改为“设备串口”，选择 `/dev/tty…` 节点并连接。
3. 点击左侧“设备信息”，可以查看系统、内存和存储信息。

Android 服务准备过程中可能请求 ADB Root，设备会短暂重连。系统和架构要求见首页的
[支持环境](../README.md#支持环境)。

## 文件上传与下载

进入“ADB 调试 → 文件传输”。左侧是电脑文件，右侧是选中设备的文件。
可双击目录进入，也可以在地址栏输入路径后按 Enter。

### 下载设备文件

1. 左侧打开本地保存目录。
2. 右侧打开设备目录，例如 Android 的 `/sdcard`，或固件使用的日志目录。
3. 在右侧选中文件或文件夹，点击“下载所选”。

### 上传到设备

1. 左侧打开源文件目录，右侧打开设备的目标目录。
2. 在左侧选中文件或文件夹，点击“上传所选”。
3. 遇到同名文件时，可选择跳过、覆盖或取消；默认跳过。同名文件夹按跳过处理。

也可以把选中项目拖到对侧文件栏传输。传输进度和结果在任务区查看，点击“停止”可取消后续传输。
中途停止后，已完成的文件会保留；刷新目录后可继续传输剩余项目。

文件列表右键菜单提供新建、改名、删除和权限编辑。删除文件会直接移除，不进入回收站。
常用设备目录可以通过收藏按钮保存。

## 投屏与设备维护

进入“ADB 调试 → 远程调试”：

- **投屏**：点击“开始投屏”，在独立窗口中查看和操作 Android 屏幕。使用“保存截图…”保存 PNG，
  点击“停止投屏”结束。投屏不转发音频。
- **导出日志**：点击“导出 Logcat”或“导出 dmesg”，选择保存位置。Logcat 用于 Android，读取 dmesg 需要相应权限。
- **Root 与 Remount**：用于调试固件中需要 root 权限或重新挂载分区的操作，量产固件可能禁用这些能力。
- **重启设备**：确认目标设备后执行，重启后等待设备重新出现在 ADB 列表中。

窗口底部的“最近操作”可以查看近期结果和后台任务。

## 设置与常见问题

连接参数、终端外观和目录偏好自动保存在 `%LOCALAPPDATA%/TestTools/`，这是项目原名沿用的设置目录。
备份设置时，退出程序后复制整个目录即可。日志保存在录制或导出时选择的位置。

| 问题 | 处理方法 |
| --- | --- |
| 启动提示缺少 DLL | 重新完整解压成品包；缺少 MSVC 运行库时安装 `vc_redist.x64.exe` |
| 串口列表为空 | 到 Windows 设备管理器检查连接和驱动，确认 COM 口已出现，再刷新串口 |
| 串口被占用 | 断开其他页面或其他串口软件中的同一端口，再连接 |
| 串口乱码或没有输出 | 核对波特率、数据位、校验、停止位、流控和 TX/RX/GND 接线，确认设备已上电并有输出 |
| 终端输入没有显示 | 输入依赖设备回显，检查设备是否已进入 Shell；回车或退格异常时在“终端选项…”调整 |
| ADB 找不到设备 | 检查 USB 数据线、ADB 驱动和设备上的 adbd；Android 设备还需开启 USB 调试 |
| ADB 显示 unauthorized | 在设备屏幕上确认 USB 调试授权 |
| ADB 显示 offline | 重新插接 USB，检查设备系统和 adbd 是否正常 |
| ADB 在线，但板端服务连接失败 | 打开“服务详情”查看原因，检查设备架构、权限和包内的 `agent-bundle/` |
| 文件访问被拒绝 | 检查目录权限和分区挂载状态，先尝试 `/sdcard` 等当前用户可访问的目录 |

反馈问题时，请附上程序版本、设备型号和系统、复现步骤及相关日志。
程序版本可在 `OhMyDebug.exe` 的“属性 → 详细信息”中查看。
