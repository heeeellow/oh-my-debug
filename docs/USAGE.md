# 使用手册

[返回项目首页](../README.md)

如果第一次使用，只需先完成“启动”和“一次串口连接”或“连接 ADB 设备”中的一条路线。
后面的录制、文件管理、投屏和设备维护可以按需要使用。

## 1. 启动程序

解压整个 Windows x64 成品 ZIP，运行 `OhMyDebug.exe`。
GitHub 的 Source code 包是源码，不包含已构建的主程序。

| 文件或目录 | 作用 |
| --- | --- |
| `OhMyDebug.exe` | 桌面程序 |
| Qt DLL、`platforms/` 等 | 界面运行库和插件，保留在程序旁 |
| `platform-tools/` | 随包 ADB 和配套文件 |
| `agent-bundle/` | Android/Linux 板端服务；设备串口和硬件信息会用到 |
| `scrcpy/` | Android 投屏工具 |
| `licenses/`、`LICENSE` | 第三方与第一方许可说明 |

Windows 提示缺少运行库时，安装包中的 `vc_redist.x64.exe` 后再启动。
日常使用选择 Release；Debug 用于开发调试，交互速度可能不同。

## 2. 先认识两种连接

窗口顶部选择的是 ADB 设备。串口页的“位置”和“串口”选择的是本次要打开的串口。
两者不是同一个列表。

| 要做的事 | 需要 ADB 在线 | 需要连接板端服务 |
| --- | --- | --- |
| 使用电脑上的 COM 串口 | 否 | 否 |
| ADB Shell、文件收发、Android 投屏 | 是 | 否 |
| 打开开发板上的 `/dev/tty…` 串口 | 是 | 是 |
| 读取板卡硬件信息 | 是 | 是 |

“ADB：已连接”表示已选中在线设备；“板端服务：已连接”表示服务通信已就绪。
串口是否打开，以串口连接栏旁的状态为准。

## 3. 完成一次本地串口连接

适用于 USB 转串口、开发板 Debug 串口，以及 Windows 能识别的其他 COM 设备。
连接前按设备说明确认线序、电平和串口参数。

1. 安装串口设备的 Windows 驱动，接好设备。
2. 左侧进入“串口调试 → 单串口调试”。
3. “位置”选择“PC端串口”，点击“刷新串口”，从列表选择实际 COM 口。
4. 设置波特率。“更多参数”中可以调整数据位、校验、停止位和流控。
   `115200 / 8N1 / 无流控` 是常见配置，仍应以设备要求为准。
5. 点击“连接”，确认连接栏显示已连接。
6. 让设备产生输出，中央区域会显示 RX 数据。需要发送时，在底部输入内容，选择行尾，再点击“发送”。

文本发送和 HEX 发送的含义不同：文本按编码发送，HEX 输入十六进制字节。
例如 `41 54` 对应两个字节，不是把这五个字符原样发给设备。
AT 等文本命令通常还需要正确的行尾，按设备协议选择 CR、LF 或 CRLF。

右侧快捷指令的“填入”只改发送框；“发送”会立即发送。
不确定指令含义时，先填入查看。普通调试不会自动识别设备协议。

同一个 COM 口不能同时在普通调试、串口终端或其他串口软件中打开。
切页会保留已有连接；换一个页面使用该端口前，先断开原页面的连接。

## 4. 使用 Debug 串口终端

查看启动日志、使用 U-Boot 或 Linux Shell 时，进入“串口调试 → 串口终端”。
选择端口和参数后连接，点击终端区域即可直接输入。

终端只显示设备发回的内容。按键已经发送但设备没有回显时，屏幕上不会出现本地输入文字。
看到 Linux Shell 提示符后，可以先执行 `pwd` 这类只读命令确认交互；其他控制台按其支持的命令操作。

| 操作 | 默认行为 |
| --- | --- |
| Enter | 发送 CR，可在终端选项中改为 LF 或 CRLF |
| Backspace | 发送 DEL，可改为 BS |
| Ctrl+C | 有选区时复制；无选区时向设备发送中断 |
| Ctrl+V | 粘贴，多行内容默认先预览 |
| Ctrl+Shift+C / Ctrl+Shift+V | 复制 / 粘贴 |
| Ctrl+Shift+F | 搜索终端内容 |

上述 Ctrl+C/V 行为以默认“智能 Ctrl+C / Ctrl+V”开启为准。
关闭后两键发送设备控制字符，仍可使用 Ctrl+Shift+C/V 复制粘贴。

“自动高亮”标记输出中的固定错误和警告词，可以随时关闭。
字体、字号、行距、配色、光标及回车/退格行为在“终端选项…”中设置。
时间栏只标记收到文字的行，空白区域不会生成接收时间。

历史回看有容量限制。要保留长时间日志，使用持续录制。

## 5. 保存日志与持续录制

- **保存日志**：导出当前显示记录，适合保存眼前的问题片段。
- **录制**：从开始录制后持续保存收发数据，适合抓取启动过程或长时间会话。

普通收发页的日志保存入口位于收发区域“更多”菜单；终端工具栏有“保存日志…”入口。
点击“录制…”选择文件和格式后开始，结束时停止录制，等待保存完成。

录制可选择带方向和时间的文本，或原始 RX 二进制，另有元数据文件。
清屏、搜索、高亮和显示历史裁剪不会删除已录制的数据。
录制失败会显示原因；磁盘空间不足或写入失败后，应检查已保存文件及结果提示。

## 6. 连接 ADB 设备

1. 使用能传输数据的 USB 线连接设备。
2. Android 设备启用 USB 调试，并在设备上确认电脑的调试授权。
   Linux 固件需要自带并启动 adbd；只有串口连接不会让它出现在 ADB 列表中。
3. 点击顶部“刷新”，从设备下拉框选择在线设备。
4. 查看 ADB 状态，再进入“ADB 调试”下的所需页面。

| 显示状态 | 先检查什么 |
| --- | --- |
| 未发现设备 | 数据线、USB 连接方式、Windows 驱动，以及设备是否已启动 adbd |
| 待授权 / unauthorized | 在设备上确认 USB 调试授权 |
| 离线 / offline | 设备系统和 adbd 是否正常，USB 连接是否稳定 |
| 已发现设备但未选择 | 在顶部列表明确选择本次要操作的设备 |
| ADB 在线、板端服务未连接 | 文件、Shell 和投屏仍可使用；仅在需要设备串口或硬件信息时连接服务 |

### 打开 ADB Shell

进入“ADB 调试 → 远程调试”，点击“打开 ADB 终端 ↗”。
程序为当前选中的设备打开独立 Windows 终端或命令提示符，直接进入设备 Shell。
终端打开后切换顶部设备，不会改变这个终端连接的目标；关闭桌面工具也不会自动关闭它。

Shell 使用设备当前权限。打开 Shell 本身不会执行 Root 或降权。

### 什么时候连接板端服务

要操作设备上的串口或读取硬件信息时，点击顶部“连接服务”。
工具会检查设备和服务版本；需要同步时，会向设备复制并启动匹配的程序。
Android 服务准备可能请求 ADB Root，并引起短暂重连，不是所有量产固件都允许此操作。

Android 服务包面向 ARMv7/ARM64，最低构建 API 为 23。
Linux 服务包面向 ARM64、glibc 2.31 及以上，自动部署要求 root adbd。
架构、libc、权限或设备节点不匹配时，保留错误信息并检查固件配置，不要反复盲目重试。

服务连接成功后，可在串口页将“位置”改为“设备串口”，选择实际节点，再单独连接串口。
“设备信息”页显示当前设备与服务信息；支持的存储信息会在服务就绪后读取。
未知字段可能来自驱动、权限或固件差异，读取完成也不代表设备测试合格。

## 7. 上传和下载文件

进入“ADB 调试 → 文件传输”。左侧是电脑文件，右侧是当前 ADB 设备文件。

**下载设备日志：**

1. 左侧打开用于保存日志的本地目录。
2. 右侧打开设备上实际的日志目录。Android 可从 `/sdcard` 等可访问目录开始，具体日志路径取决于固件。
3. 选择右侧文件或文件夹，点击“下载所选”。
4. 查看任务结果；完成后在左侧目录确认文件。

**上传文件：**

1. 左侧打开源文件所在目录，右侧打开实际目标目录。
2. 选择左侧文件或文件夹，点击“上传所选”。
3. 如遇同名项目，按提示选择跳过、覆盖或取消。默认跳过；当前不合并已有同名文件夹。
4. 查看任务结果，再刷新设备目录确认。

手工修改地址后，要按 Enter 打开目录，收发目标才会更新。
拖入对侧文件栏也可以发起传输。收藏按钮用于保存当前已打开的设备目录。

新建、改名、删除和权限编辑位于文件列表右键菜单。
删除是直接删除；修改前核对当前设备、目录和所选项目。
只读分区或权限不足会显示错误，文件页不会自动 Root、Remount 或安装 APK。

“停止”取消后续传输或等待，已经完成的操作会保留。
失败或停止后刷新目录，按结果中的失败项目重试。

## 8. 投屏、日志导出和维护

“ADB 调试 → 远程调试”还提供以下功能：

- **Android 投屏**：选中在线 Android 设备后点击“开始投屏”，画面在独立窗口打开。
  可以操作设备、保存 PNG 截图；结束时点击“停止投屏”。当前不转发设备音频，也不支持 Linux 桌面投屏。
- **导出 Logcat / 导出 dmesg**：选择保存位置后导出日志。Logcat 面向 Android，dmesg 是否可读取决于设备权限。
- **Root 与 Remount**：用于需要更高权限或可写挂载的调试场景，是否成功取决于固件。
- **重启设备**：核对当前设备后确认执行；等待 ADB 重新出现不等于所有系统服务已经启动完成。

普通文件收发、Shell 和投屏不要求先点击 Root 或连接板端服务。
维护操作会改变设备状态；连接其他测试任务时，应先结束冲突任务，再操作。

## 9. 计划发送和双端调试

普通发送区的“定时 / 次数…”用于重复发送指定内容。
先确认待发送数据、行尾、间隔和次数，再启动；它与双端链路测试是两种独立任务。

“双端调试”提供 A/B 两个端点，可以分别观察或进行双向验证。
A/B 不能指向同一个串口；当前每台板端服务只允许一个活动设备串口会话。
可靠性测试会发送测试帧，开始前确认连接的是待测链路，避免把测试帧送入 Debug Shell 或其他协议设备。

底部“最近操作”显示近期结果，有后台任务时可查看和停止对应任务。

## 10. 设置、常见问题和反馈

连接参数、终端外观和目录偏好自动保存在 `%LOCALAPPDATA%/TestTools/`。
改名后继续使用这个目录，升级时无需手动迁移。
需要备份设置时，先正常退出程序，再复制整个目录；录制文件按自己选择的位置另行保存。

| 问题 | 处理方式 |
| --- | --- |
| 解压后找不到 EXE | 确认拿到的是 Windows 成品包，不是源码 ZIP |
| 提示缺少 DLL | 完整重新解压成品包；缺少 MSVC 运行库时安装包内 `vc_redist.x64.exe` |
| 刷新后没有 COM 口 | 检查 Windows 设备管理器中的串口驱动和连接，确认系统先能识别设备 |
| 提示串口被占用 | 断开本工具其他页面或其他软件中的同一端口，再连接 |
| 串口乱码或一直没有输出 | 核对串口参数、接线以及设备是否正在输出；单纯打开 COM 口不代表设备已响应 |
| 终端输入不显示 | 检查设备回显、Shell 状态和连接；终端默认不做本地回显 |
| ADB 在线但服务连接失败 | 查看“服务详情”或“设备信息”中的原因，核对随包文件、设备架构和权限 |
| 文件访问被拒绝 | 先选择当前权限可读写的目录，再判断是否确实需要调整设备权限 |

报告问题时附上版本、Windows 版本、设备型号/系统、所在页面、复现步骤和相关日志。
程序版本可在 EXE 文件的“属性 → 详细信息”中查看。
发送日志前去掉设备序列号、个人路径、账号和业务数据。
