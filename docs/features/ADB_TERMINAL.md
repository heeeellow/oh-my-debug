# ADB 终端功能契约

[返回产品设计](../PRODUCT.md) · [查看当前状态](../STATUS.md)

## 1. 用户任务

为全局当前选择的在线 ADB 设备打开系统终端，直接进入交互式 Shell。Android 与 Linux ADB 设备共用此入口，
无需 root、部署或连接 TestTools Agent。应用不接管用户在终端中输入的命令。

## 2. 行为

- 左侧“ADB 调试 → 远程调试”的 ADB Shell 区提供“打开 ADB 终端 ↗”；文件页不重复提供快捷入口。它是启动动作，不是独立子页面。无设备、离线、待授权和离线演示时禁用，提示原因。
- 点击时固定当前设备序列号，以 `adb -s <serial> shell` 启动；随后切换设备不改变已经打开的终端。
- 打开前在后台只读核对 `id -u`，页面和活动提示显示启动时的实际 UID；核对失败显示权限未知，仍可打开终端。此快照不代表终端打开后的权限持续不变。
- Shell 继承设备当前 adbd / 系统启动配置的权限，入口本身不执行 `root`、`su` 或 `unroot`。Android 板端服务部署可能已请求 `adb root`；因此“本次没有点击 Root”不等于当前 Shell 一定是普通用户。不会为了打开普通终端自动降权并中断已有连接。
- 应用发现、部署与终端使用相同的 ADB 选择规则：显式构造参数、`ADB_PATH`、程序旁
  `platform-tools/adb.exe`、SDK 环境目录、系统 PATH。`ADB_PATH` 可指定文件或目录。
- 优先打开 Windows Terminal；无法创建或启动器立即报错时回退到新建的 Windows 命令提示符，
  命令提示符在 Shell 退出后保留，便于查看断线或启动错误。
- 启动工作在后台完成，期间阻止重复点击；失败在活动栏显示原因并允许重试。
- 启动成功表示系统终端已创建；设备在启动后掉线或拒绝 Shell 时，由终端展示 ADB 错误。
- 终端作为独立窗口存在，关闭 TestTools 不关闭它；应用不等待 Shell 退出，也不重启共享 ADB server。

## 3. 打包与实现

- 固定的第三方工具位于 `third_party/platform-tools/`，只包含 ADB、两个配套 DLL、原始 NOTICE、版本说明与摘要清单；
  构建自动复制到输出目录，不在增量构建中下载工具。来源与版本见 [第三方依赖](../THIRD_PARTY.md)。
- UI 只提交选中设备并映射启动结果；`AdbTerminalService` 校验设备状态，ADB 适配器绑定路径与参数，
  `ProcessRunner` 负责 Windows 外部终端启动。核心路径保留简短注释说明参数转义、回退与窗口所有权。
- Agent 协议和串口会话不变；外部交互式 Shell 不属于 Agent RPC 或测试执行通道。

## 4. 本轮验收

本轮按实际改动验证，不为此功能扩展通用测试框架：

- Release 构建与输出目录 ADB、DLL、NOTICE 复制正确；无 SDK 环境时能找到内置 ADB，显式覆盖仍优先。
- 启动参数固定目标设备；Windows Terminal 启动与 cmd 回退可用，中文和空格路径能够启动。
- 在线设备按钮可用；无设备、离线、待授权时禁用；启动失败可见且能重试。
- 1366×768 与 1920×1080 的远程调试页入口无裁切，原串口主流程可用。
- 文档与静态检查通过；真实设备 Shell 的验证范围单独记录在 `STATUS.md`。
