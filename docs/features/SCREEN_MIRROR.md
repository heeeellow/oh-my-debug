# Android 投屏功能契约

[返回产品设计](../PRODUCT.md) · [查看当前状态](../STATUS.md)

## 使用任务与入口

为顶部选中的在线 Android ADB 设备打开独立投屏窗口，直接用鼠标和键盘操作设备。
左侧“ADB 调试 → 远程调试”集中展示 ADB Shell 与投屏控制，两者分别启动；页面切换不启动投屏，点击“开始投屏”才启动独立画面。
无需 root 或 TestTools Agent；Linux ADB 设备提示不支持，Windows 本地串口独立工作。

## 会话与操作

- 同时管理一个投屏，会话固定绑定启动时的设备序列号。切换顶部设备不会迁移已有投屏，面板明确显示其目标；停止后可启动当前所选设备。
- 控制面板突出开始/停止、电源键与保存 PNG 截图；返回、Home、多任务及音量收进“更多操作”。鼠标拖动、键盘输入、APK 拖放安装和全屏由独立 scrcpy 窗口处理，文件页上传不触发安装。
- 页面内嵌画面仍是候选：原生窗口挂接、回嵌、焦点、中文输入、DPI 和 APK 拖放须独立验收，不能仅凭窗口句柄接入就改为默认；当前评估结果见 STATUS。
- 控制和截图均使用正在投屏的设备，不使用随后变化的全局选择。保存文件由用户选择，不在板端创建截图文件。
- 默认关闭音频转发，最大画面边长 1920、最高 60fps；不主动修改分辨率、常亮、网络 ADB、root 或共享 ADB server。
- 无设备、待授权、离线和离线演示时不能启动；启动时只读核验 Android API。启动、控制、截图和停止在后台执行。
- 只有检测到视频纹理初始化才显示“投屏中”，启动超时或进程退出展示原因并允许重试；正常关闭投屏窗口回到未投屏状态。
- 切换页面保留投屏；关闭 Oh My Debug 会先在后台关闭它创建的投屏进程并结束文件传输。只关闭本次创建的窗口/进程，不结束其他 scrcpy 或 ADB server。

## 分层与打包

`ScreenMirrorService` 拥有会话目标和状态，核心接口为固定控制枚举；scrcpy 适配器负责 Windows 子进程、
私有启动环境和固定 ADB 命令。Qt 面板只拥有控件、后台调度和 GUI 线程映射，不提供任意 shell 输入。

固定官方 Windows x64 scrcpy 包随程序分发，ADB 只使用项目现有解析器选出的路径；子进程通过自己的
`ADB` 环境变量接入，不修改宿主环境。版本、摘要和许可见 [第三方依赖](../THIRD_PARTY.md)。

## 验收

- 核心检查覆盖离线拒绝、目标固定、重复启动、退出清理、固定控制及截图归属。
- Windows 检查随包工具、启动失败、提前退出、停止与关闭；参数与中文路径不经过 shell 拼接。
- 1366×768、1920×1080 检查导航和投屏控制页，设备状态与进程状态分开显示。
- 真实 Android 单独验证画面、基本操作、截图与停止；假进程和主机检查不能替代真实投屏。
