# 串口工作台功能契约

[返回产品设计基线](../PRODUCT.md) · [查看当前状态](../STATUS.md)

## 1. 目标与边界

串口工作台为 PC端串口（当前为 Windows COM 口）和板端串口提供一致的连接、收发、计划发送、AT 快捷指令、双端调试和
可靠性压测体验。协议专用能力通过复用同一串口会话的独立工具扩展。
Debug 控制台通过“串口终端”进入，行为与验收见 [串口终端契约](SERIAL_TERMINAL.md)。

采用显式任务模式的原因和取舍见
[`ADR-0001`](../decisions/0001-serial-workspace-modes.md)。

普通发包与压测不解释 Shell 或模块业务，不自动识别所有串口协议，也不以强制抢占系统进程的方式
打开被占用设备。串口终端显式发送用户键盘数据，Agent 不增加 shell RPC。

## 2. 页面模式

左侧“串口调试”展开单串口调试、双端调试、串口终端，与 ADB 子页采用相同导航。父级恢复本次运行的当前子页，箭头只展开/收起；页面标题显示具体方式，不在顶部重复提供页签。单/双串口调试内部，已有计划发送、双向验证、可靠性压测，或切换会隐藏仍活动的端点 A 时，拒绝切换并保留原导航选择与连接。串口终端有独立会话，切页保留任务；同口占用和迁移规则见终端契约。

### 调试服务与串口的状态

顶栏区分 ADB 与“板端服务”状态，旁边提供“连接服务”“服务详情”或“重试连接”。服务就绪需要握手、版本和串口能力校验。
选择设备串口但服务未就绪时，在对应端点连接动作的位置内联显示原因和“连接服务 / 重试连接”；替换该处状态与串口连接按钮，不新增提示行或每次弹确认框。
正在连接或无在线授权设备时禁用准备入口；准备过程展示真实检查、文件准备、连接校验和能力读取步骤，连接失败原因保留在设备信息和提示中。本地 COM 活动不禁用服务准备、断开或重连；活动设备串口仍保留维护保护。
服务未就绪只限制设备串口，PC端串口独立可用；具体串口打开/断开状态继续在端点旁显示。

单串口、双端和串口终端的来源统一显示“PC端串口 / 设备串口”，路由摘要使用“PC端 / 设备”。
“刷新串口”按当前端点来源执行：PC 侧仅枚举主机 COM，不请求设备串口；不受 ADB、板端服务未连接/启动/失败/清理、设备端扫描或维护影响。
当前端点活动时锁定自身刷新；另一端活动不阻止空闲 PC 端点刷新，不改变已有连接，手动输入的端口仍保留。
设备串口刷新须服务就绪、无活动设备串口且未在扫描/维护；不满足时禁用并提示原因。
自动初始化可更新两侧列表，但设备服务缺失不再用“请先连接服务”覆盖 PC 刷新结果；PC 刷新独立报告实际枚举结果。

已连接服务每 3 秒在独立后台控制连接上执行固定只读握手和能力检查，不复用活动串口控制连接、不新增 Agent RPC。
健康检查每次 socket 收发超时 1500ms；连续两次检查失败后撤销旧服务端口、异步结束关联设备串口并显示重试，不自动发送、重装或无限重连。
旧设备/旧连接代次的检查结果不得影响新会话；ADB 状态依据设备发现结果独立显示，服务失败不冒充 ADB 断线。

### 2.1 单串口调试

默认模式，只显示一个当前端点：

- 顶部连接栏：单串口模式下将位置、串口、波特率与“刷新串口、更多参数、状态、连接”合并为同一行，
  限制下拉框最大宽度以避免宽屏过度拉伸；数据位、校验、停止位和流控放在“更多参数”。
- 中央终端：按时间顺序显示 TX、RX 和状态提示，支持动态切换 HEX 显示、时间戳和自动滚动；每次
  接收独立记录，方向以颜色区分，“更多”菜单提供计数清零和日志保存。
- 右侧快捷指令：列表提供逐项填入/发送，顶部收起，收发记录工具条提供展开入口；折叠只改变横向空间。
- 底部发送栏：输入框下方工具栏左侧为 HEX 发送与行尾，右侧为“清空”“定时 / 次数…”和“发送”；
  未连接时突出“连接”，连接后“断开”使用次级样式。

连接后仍允许查看参数，但会锁定会改变当前文件描述符配置的控制。断开后恢复编辑。

### 2.2 双端调试

显式切换后显示端点 A/B。每个端点可独立连接、收发和监视，也可执行双向验证。两个端点不得指向
同一个串口资源；当前 Agent 只支持一个板端会话，因此两个端点不能同时选择两个板端串口。

可靠性压测是双端调试中的按需子功能，因为它同样依赖端点 A/B 和实际链路。它复用两端连接配置，
但不复用手工发送内容、普通定时/次数发送状态或结果。

连接与测试入口保留在顶部；双向验证与压测结果集中在两端工作区下方，文字可选中复制。压测总结果、
A→B 和 B→A 的统计分别占行，长内容自动换行，不与顶部操作按钮争用宽度；切回单端时隐藏结果区。

### 2.3 可靠性压测

从双端调试中的独立入口打开参数面板，使用确定性测试帧。开始前显示方向、帧数、载荷大小、间隔、
预计时长和资源占用；运行中显示进度、停止动作和结构化统计。

可靠性结果至少分开报告：发送帧、解析帧、丢帧、重复帧、格式/CRC 错误、可比较载荷位和 BER。
不得用一个含义不清的“综合误码率”掩盖丢帧或坏帧。

### 2.4 快捷指令（AT / HEX）

快捷指令是单串口模式中的轻量协议工具，不是第二套串口发送引擎：

- 本地指令库最多保存 64 条，每条包含名称、指令正文与可选的 HEX 十六进制格式标记（兼容 v1/v2 存储）；
- 侧栏列表显示名称和指令预览（HEX 带 `[HEX]`），长文本省略并保留完整提示。每项提供“填入”（同步发送框及
  HEX 状态，不发送）和“发送”（立即发送）；选择列表项不发送；
- 侧栏展开偏好与宽度保存于 `serial-preferences.json`，宽度默认 240、范围 220–480 逻辑像素；旧配置缺失宽度时使用默认值。
  窄屏可自动收起，自动适配不改写保存的展开偏好或宽度；显式收起后调整窗口仍保持关闭；
- 发送数据区只保留一个行尾选项，固定为“无、LF、CR、CRLF”；手动发送与文本快捷指令共用，
  单串口首次使用默认选择常见的 CRLF；HEX 快捷指令按原始字节直接发送，不追加行尾；
- 首次使用提供“AT、ATI、AT+CSQ、AT+CPIN?、AT+CREG?”五条可编辑的常用查询；
- 连接或选择变化不能自动发送；计划发送、链路验证或压测期间禁用快捷填入/发送，避免改变当前任务；
- 快捷发送复用当前端点的 `SerialSession`、有界发送队列、TX 显示、字节统计与错误状态；
- 管理窗口支持新建、修改和删除，可勾选 HEX 格式并进行十六进制合法性校验；
- 指令库与串口界面偏好（`serial-preferences.json`）存储在当前 Windows 用户的本地应用数据目录，
  测试和离线快照可通过 `TESTTOOLS_DATA_DIR` 隔离，不随设备切换、Agent 部署或板端固件分发。

首版不提供脚本、条件判断、批量顺序执行、延时宏、响应解析或根据端口自动识别模块。某条指令是否被
具体 4G 模块或外设支持仍由对应设备手册决定。

### 2.5 模式切换与状态保留

- 应用启动后首次进入串口页默认使用单串口调试；同一次应用会话中返回页面时保留当前模式和连接。
- 模式切换不能静默断开串口或丢弃输入。目标模式无法安全复用当前资源时，先说明影响并让用户停止
  任务或断开连接。
- 定时/次数发送和可靠性压测不能在页面不可见且没有全局状态与停止入口时继续运行；初版可以阻止
  离开或切换，后续只有在全局活动栏完整承接进度和停止动作后才允许后台继续。
- 切换全局设备前必须处理该设备上的活动连接和任务，避免把旧设备数据显示在新设备上下文中。

### 2.6 搜索与过滤

- 收发记录标题栏提供“搜索”入口，`Ctrl+F` 聚焦当前端点的搜索栏；默认收起，关闭或 Esc 清除过滤并恢复保留日志。
- 使用区分大小写的字面量匹配，按当前文本/HEX 显示搜索，提供匹配计数、上一个/下一个和“仅看匹配”；
  Enter/F3 向下查找，Shift+F3 向上查找。导航匹配时暂停自动滚动，可显式重新勾选。
- 过滤只选择缓冲中符合条件的记录，不改动原始字节或计数；取消过滤恢复仍在缓冲中的全部记录。
- 接收更新按短周期合并刷新搜索/过滤视图；日志超出 2000 条或 512 KiB 后淘汰旧记录并显示“已截断”。
- “更多 → 保存当前日志…”保存当前显示内容，过滤开启时只保存匹配视图；不代表从连接开始的完整原始抓取。
  计数清零也位于“更多”；空间不足时 HEX 显示、时间戳、自动滚动移入该菜单，状态与可见开关一致。

### 2.7 指令库导入导出

- 在快捷指令侧栏的“指令库”菜单中提供管理、JSON 导入和导出；导入前展示条数并确认替换当前指令库。
- 沿用 v1/v2 JSON、64 条、名称/正文长度和 HEX 校验；文件不存在、损坏、版本不支持或保存失败时保留原库。
- 导入仅替换指令，保留当前发送数据区行尾；文件中的历史行尾不覆盖当前设置，也不触发任何发送。
- 导出当前指令库为 v2 JSON，可供另一台电脑导入；不改变串口参数或连接。

### 2.8 本地控制线与高速波特率

- 波特率增加 `230400`、`460800`、`1500000` 预设，仍允许手动输入；实际支持由串口和驱动决定。
  本轮不修改板端 Agent，已有板端波特率支持范围不变。
- “更多参数”提供 DTR/RTS 开关，仅在本地串口已连接且没有计划发送/链路测试时可操作；硬件流控时禁用手动 RTS。
- 半选表示本次连接尚未手动设置，勾选/取消分别请求置位/清除控制线；仅显示驱动接受的设置，不宣称测量到物理电平。
- 操作经过当前会话代次在后台执行；驱动不支持、握手控制冲突或断线时返回原因，失败恢复原选择。
- 连接、重连和恢复界面偏好均不额外发送控制线设置，不记忆电平；端口打开/关闭本身的驱动行为仍由硬件决定。

### 2.9 持续录制与关键字高亮

- 单/双串口与独立终端的标题栏保留“录制…”入口。连接后手动选择路径及格式：默认带标记 UTF-8 文本
  `.log`，或只含原始 RX 的 `.bin`。两种格式均另写 `<文件名>.json` 元数据；覆盖任一已有目标必须确认。
- 提交录制后立即缓存新数据，由后台打开文件；准备期间可停止。RX 在投递显示前保存，TX 只记录传输报告成功的写入，
  与本地 TX 显示开关无关。文本按采集时间和方向分批写出，跨批次增量处理 UTF-8；非法编码和非换行/制表控制字节转义为 `\xNN`。
  原始格式不混入 TX、时间戳或提示。元数据记录连接目标、串口参数、起止时间、接受/写入/拒绝字节及完成或失败原因。
- 录制队列最多等待 `4 MiB` 数据或 `8192` 批次；满时停止接受新数据，报告失败并尽量排空已接受部分。
  磁盘打开、写入、flush、关闭或元数据保存失败均不能显示完成；保留已经生成的文件，错误不关闭串口。
- 停止、断线与退出先停止入队，再异步排空并关闭文件；保存期间禁用重复开始，窗口退出等待录制收尾。
  切页、清屏、搜索/过滤、计数清零和显示截断不改变录制内容；同一 B 会话在单/双模式间复用时继续录制。
  完整性只覆盖会话已收到并成功保存的数据，不证明物理链路没有丢字节。文本用于阅读，逐字节分析使用原始格式。
- “高亮”只叠加显示样式，按文本块增量匹配，不改动原始缓冲、保存文本或发送字节。固定词按大小写不敏感的独立单词匹配：
  错误为 `ERROR / FAIL / FAILED / panic / Exception / Segfault`，警告为 `WARN / WARNING / timeout`。
  搜索选区显示在高亮之上，关闭搜索仍保留高亮，关闭高亮恢复 ANSI/方向样式。开关按通道保存在原有偏好文件，旧文件默认关闭。

### 2.10 显示积压与后台任务

- 接收显示队列最多等待 `1 MiB` 或 `2048` 批次，合并投递通知；每次消费默认最多 `128 KiB / 128` 批次
  （单批较大时允许消费该批）。保留普通接收批次边界，淘汰最旧数据时显示截断及跳过数量提示，计数仍以会话实际收到的字节为准。
- 显示缺口结束半个 UTF-8/ANSI 序列，后续数据重新解析。若双向验证或可靠性压测受影响，停止并报告结果不完整，不能当作通过。
  独立录制位于此队列之前，其完成状态单独判断。
- 全局底栏按快照汇总录制、计划发送、压测与文件传输，切页后仍可查看。展开后明确提供“停止录制 / 停止计划发送 / 停止压测 / 取消传输”，
  保存中的录制显示等待保存。停止不等于断开串口，旧任务入口不能作用于随后启动的新任务。

## 3. 连接状态模型

```text
disconnected -> connecting -> connected -> disconnecting -> disconnected
                    |              |
                    v              v
                  error <------ reconnecting
```

- 每次异步结果必须属于当前连接代次，旧回调不能覆盖新状态。
- `connected` 只表示传输通道建立，不表示外设一定会响应。
- 连接失败应区分设备不存在、权限不足、被占用、参数不支持、Agent 离线、转发失败和连接超时。
- USB 虚拟串口的 termios 波特率可能只是兼容字段；界面区分请求值和驱动报告值，不宣称物理速率。
- 断开必须停止新发送、取消读写、结束计划任务并等待后台资源退出，不依赖无限阻塞。

新端点的初始配置为 `115200 / 8 数据位 / 无校验 / 1 停止位 / 无流控`。应用可以按稳定端点标识
记住最近一次成功连接的配置，但自动恢复后的值必须完整可见；端点消失、驱动拒绝参数或 Agent
报告不同有效值时不能把历史配置显示成已经生效。

## 4. 收发语义

### 4.1 发送输入

- 通用占位文字为“输入要发送的数据”。
- 文本模式按 UTF-8 编码；HEX 模式忽略允许的空白并拒绝奇数半字节和非法字符。
- 手动发送只发送当前输入和用户明确选择的行尾，不根据端口名称修改载荷。
- 空输入默认不发送；若未来需要仅发送行尾，必须提供明确动作而不是依赖空白输入。
- 默认按 Enter 发送，Shift+Enter 插入输入内容中的换行；发送按钮行为与 Enter 完全一致。若后续允许
  用户修改快捷键，设置必须在发送区可发现，不能让相同按键在文本/HEX 模式产生不同发送语义。

### 4.2 行尾

行尾选项固定为“无、LF、CR、CRLF”，分别追加零字节、`0A`、`0D`、`0D 0A`。HEX 模式默认不
追加；用户仍可显式选择其他值。切换端口、刷新设备或重新连接不得覆盖用户已经选择的行尾。

### 4.3 协议扩展

AT、Modbus 等协议工具使用独立的参数、解析和验收契约，并复用底层串口会话。通用发送区只处理
用户输入、编码和行尾，不根据端口名称推断协议。

### 4.4 监视器

- 每条记录带有 TX、RX 或状态方向；TX 为棕色，RX 为蓝绿色，状态提示为中性灰。保留方向文字，
  颜色在追加、切换显示方式、搜索过滤和缓冲截断后的重绘中一致。TX 表示 TestTools 已写入的数据，不代表外设回显。
- 文本/HEX 与时间戳是显示方式，不改变已经接收和保存的原始字节；切换“HEX 显示”或“时间戳”会即时重绘
  当前缓冲区内的已有记录。
- 每次接收回调独立起行，内部遇到 LF 再分行，不按时间间隔拼接其他回调；各行保留该次接收的时间戳。
  接收批次由传输层决定，不代表协议帧或发送方的一次写入。完整 UTF-8 正常显示，不完整/非法字节立即显示
  为 `\xNN`，不暂时隐藏或等待下一次接收；HEX 可查看原始字节，显示分行不向原始数据插入换行。
- 本地串口按 RX 到达事件交付数据，最少 1 字节即通知，不用接收空闲窗口合并通知；显示刷新可批量进行。
- 提供“自动滚动”开关（取消勾选时保持当前滚动位置与文本选择）；“更多”中的计数清零只归零当前端点
  RX/TX 字节计数，日志保存导出当前显示内容为 `.log/.txt`，两者均不清空日志。
- “清空”使用可识别的次级按钮，不得弱化成灰色文字链接；接收区“清空”位于收发记录标题行右侧，发送框
  “清空”位于发送输入框下方工具栏（与“定时 / 次数…”和“发送”同排），避免视觉归属混淆。
- 清空接收记录保留字节计数；计数清零保留记录。两个动作独立，提示文字明确各自保留的内容。
- 大数据流采用有界缓冲、批量刷新和明确的截断提示，不能无限增长或阻塞 GUI。

## 5. 定时与次数发送

计划发送复用当前用户载荷、编码和行尾，但不属于可靠性压测。用户可以设置：

- 间隔；
- 发送次数，或明确选择持续发送；
- 是否立即发送第一条；
- 运行中停止。

开始后锁定会改变载荷的控制，显示已发送次数和下一次时间。发送失败、连接断开、达到次数或用户
停止都必须产生确定的结束原因。间隔低于按当前帧长和串口格式估算的可实现时间时，应提示并使用
可实现值，避免仅在主机队列中堆积。

## 6. 错误与安全

- 权限不足时显示节点、当前身份和建议的安全处理方向，不默认执行永久 `chmod 777`。
- 被 `rild` 等系统服务占用时显示占用者并阻止强制抢占。
- Agent 离线时保留当前输入和参数，提供连接入口，但不能显示成串口参数错误。
- 真实 AT 冒烟、自动发送和可靠性压测均会向设备写数据，测试前必须明确区分于无发送连接检查。

## 7. 分层归属

| 能力 | 归属 | 说明 |
| --- | --- | --- |
| 页面布局、文案、焦点和可见状态 | Qt UI | 只映射状态和收集意图 |
| 串口会话、计划发送用例、模式状态 | Application | 不依赖 Qt，协调 core 接口 |
| 编解码、行尾、发送队列、测试帧和校验 | Core | 标准 C++，可独立测试 |
| Windows COM 访问 | Local adapter | 通过 `ISerialTransport` 接入 |
| 板端节点访问和资源独占 | Agent | POSIX/平台适配，无 Qt |
| ADB 发现、部署和端口转发 | Transport/deployment | 不解释串口业务 |

### 7.1 `SerialSession` 应用契约

一个 `SerialSession` 只代表一个串口端点，并拥有该端点的 `ISerialTransport`、连接代次、异步发送
队列、收发字节统计和普通计划发送。调用者负责选择端点并创建传输，不能同时给同一会话注入两个传输。

- `open` 先收敛旧连接，再为新连接分配代次；数据、状态和发送完成回调都携带该代次。
- `send` 只表示载荷被有界发送队列接受；只有底层写入成功后才增加 TX 字节并产生成功完成回调。
- `startScheduledSend` 拒绝空载荷、未连接状态、非法间隔和重复启动；`processScheduledSend` 由应用
  时钟驱动，不在 Qt 定时器中保存计划业务状态。
- 计划快照中的 `submitted` 表示已进入发送队列的次数；实际写入字节以会话 TX 统计为准。达到次数、
  用户停止、写入失败、连接异常或断开都会停止计划。
- `closeAsync` 立即进入 `Disconnecting` 并停止接受新发送，在后台等待发送线程和传输退出；完成回调
  仍携带关闭代次。析构和同步 `close` 用于退出或重连边界，必须确定等待资源结束。
- 会话回调可以来自后台线程，不得直接访问 Qt 控件；Presentation 必须切换到 GUI 线程，并在执行
  已排队的界面回调前再次核对代次。
- 会话拥有独立 `SerialRecorder`，所有文件操作由录制线程完成；有界入队先于显示回调。`closeAsync` 在后台等待录制收尾后完成关闭。
  录制、发送计划各有独立任务 ID，停止动作核对目标，不能只凭当前串口代次操作后来重启的任务。

## 8. 验收矩阵

| 场景 | 最低验收 |
| --- | --- |
| 默认进入串口页 | 直接看到单串口连接与发送主流程，不要求理解端点 A/B |
| 调试服务状态 | ADB 与服务状态分开显示；设备串口在服务未连接/连接中/失败时有原因与受控重试入口；失联清除旧端口，旧代次不覆盖新连接，本地 COM 仍独立可用 |
| 通用串口 | 占位文字、编码和行尾均可见，端口名称不改变发送语义 |
| AT 快捷指令 | 指令名称、正文和发送数据区唯一行尾可在重启后恢复；管理窗口与快捷栏不重复行尾；选择不自动发送，快捷发送进入正常 TX 记录 |
| 快捷指令侧栏 | 逐项填入不发送、文本/HEX 实际字节正确；折叠不改变发送区垂直位置，展开偏好与宽度可恢复，窄屏自动收起不改写偏好 |
| 连接栏与工具菜单 | 状态与按钮可区分，服务提示显隐不挤动日志；更多菜单的显示开关与原控件状态一致，保存/清零语义保持 |
| 文本/HEX | TX 与 RX 原始字节一致，非法 HEX 有明确提示 |
| 串口参数 | 默认值可见；数据位、校验、停止位和流控生效或返回明确不支持 |
| 四种行尾 | 实际发送字节分别与无追加、LF、CR、CRLF 一致 |
| 搜索/过滤 | Ctrl+F 展开，匹配计数与导航正确；文本/HEX 与 UTF-8 搜索可用，关闭恢复缓冲内容，截断可见 |
| 持续录制 | 原始 RX 逐字节一致且无 TX/前缀；文本跨批 UTF-8 与成功 TX 正确；超过显示上限、清屏/过滤/切页不丢录制数据；停止/断线/退出排空 |
| 录制异常 | 打开/写入/flush/关闭/元数据失败与队列超限可见，不误报完成，不断串口；已有文件未确认不能覆盖，旧任务停止无效 |
| 关键字高亮 | 固定词大小写策略一致；与搜索叠加、关闭后恢复 ANSI；原始缓冲和文本导出不变，偏好可恢复 |
| 显示积压与任务 | 字节和批次数有界，通知合并；缺口有提示且测试停止，录制不受显示丢弃影响；底栏真实汇总并可独立停止各任务 |
| 指令导入/导出 | v1/v2 与 HEX 往返正确；损坏/缺失/保存失败保留原库，导入不改变当前行尾或发送任何数据 |
| 本地控制线 | 默认不额外设置，手动操作有结果；旧代次不能操作新连接，断线/握手冲突失败可见，Agent 禁用 |
| 键盘发送 | Enter 与发送按钮载荷一致，Shift+Enter 只修改输入且不触发发送 |
| 本地 TX 显示 | 无论外设是否回显，每次成功写入均显示一条 TX |
| 接收批次与方向 | 同毫秒无换行的两次接收仍分别记录，原始字节不变；不完整 UTF-8 可见；TX/RX 颜色在 HEX、过滤和重绘后保持一致 |
| 清空与清零 | 清空只删除日志，清零只重置计数；连接、发送输入和另一端不受影响 |
| 定时/次数发送 | 可独立启动、计数和停止，不进入可靠性压测状态 |
| 双端调试 | 两端可独立操作；双向验证和可靠性压测入口清楚，同资源冲突和 Agent 单会话限制可理解 |
| 双端结果 | 1366×768 下结果位于两端工作区底部，方向分行且可复制；通过、失败与停止结果均不遮挡按钮或相互覆盖 |
| 模式与设备切换 | 不静默断开或隐藏活动任务，输入和状态归属不会串到其他设备 |
| 异常断开 | 计划任务停止，状态收敛，无旧回调覆盖和界面卡死 |
| 占用/权限/离线 | 错误分类正确，保留输入，不执行高风险自动修复 |
| 窗口与键盘 | 在界面设计规定的尺寸和 DPI 范围内无关键裁切，Tab 顺序和焦点可见；每批按开发手册第 5.2 节选受影响页面与状态，不逐项展开全部组合 |
| 退出 | 活跃连接和后台线程确定性结束，无终端残留或无限等待 |
