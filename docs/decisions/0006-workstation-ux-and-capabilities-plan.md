# ADR-0006：顶栏重塑、工作台交互升级与板级实用能力详细设计方案

[返回当前状态](../STATUS.md) · [产品设计](../PRODUCT.md) · [界面设计](../UI_DESIGN.md) · [总体架构](../ARCHITECTURE.md) · [上一轮方案（ADR-0005）](0005-adb-workspace-terminal-and-files.md)

- **日期**：2026-10-29
- **状态**：分批实施。当前已实施范围与验证完成度见 `STATUS.md`；尚未落地的内容继续作为规划。
- **核心策略**：
  1. 保持 Qt Widgets 技术栈与暖白中性配色，改善**操作层级、可用空间、状态辨识与操作关联**，优先保证连接、看日志、发指令和传文件的主流程。
  2. 围绕嵌入式板卡研发与测试高频场景，补齐**串口实时流式录制、只读关键字高亮、单串口右侧快捷指令栏、ADB 常用目录书签、受控文件操作、ADB 快捷维护动作及板卡只读硬件核验**。

- **文档职责**：本文保存本轮方案、关键取舍与实施顺序；功能落地时同步更新对应 `features/` 契约和 [`UI_DESIGN.md`](../UI_DESIGN.md)，实现、构建与实机验证记录唯一由 [`STATUS.md`](../STATUS.md) 汇总。

## 1. 现状问题诊断汇总

以下判断来自 `v0.9.0` 已有界面快照、样式表（[`src/ui/theme.cpp`](../../src/ui/theme.cpp)）与各页面代码。控件位置和功能缺口可以由现状确认；辨识度、密度与布局收益属于设计判断，需要由改动后的启用态、禁用态和目标尺寸快照核对。

### 1.1 UI 布局与视觉交互问题（8 项）

| 编号 | 所在区域 | 现状问题 | 影响 |
| --- | --- | --- | --- |
| U1 | **顶部全局栏** | 称呼板端 Agent 为“设备串口服务”，按钮叫“连接 / 准备” | 服务还提供系统信息和只读检查，可用“板端服务”统一命名，按钮直接说明连接动作 |
| U2 | **顶部全局栏 & 串口栏** | `ADB · 未连接`、串口状态带圆角边框和灰底，服务状态则为无底色文本 | 状态标签与按钮的视觉表达不统一，可能影响可点击性的判断 |
| U3 | **顶部全局栏** | `[刷新设备]` 位于顶栏最右侧，与左侧设备下拉框距离较远 | 操作入口与刷新对象的关联不够直接 |
| U4 | **单串口 / 全局按钮体系** | `[发送]` 已使用 `primaryButton`，未连接时按禁用样式呈灰色；`[连接]` 尚未作为未连接状态的主动作突出，工具按钮也有多套样式 | 需要按连接状态分配视觉重心，并统一常规、工具和危险动作的表达；禁用态快照不能作为发送按钮缺少主样式的证据 |
| U5 | **单串口 / 串口终端** | 外层 `QGroupBox#endpointCard` 内又有 `terminalFrame` 和 `composerFrame` | 单通道可减少重复框线和外层留白，将空间让给日志；双端仍需明确区分 A/B |
| U6 | **左侧导航栏** | 一级导航选中态只有左半边按钮是圆角块，右侧展开箭头 `▾` 悬在圆角外，且使用粗糙的原生黑三角（`Qt::DownArrow`） | 与右侧下拉框统一使用的抗锯齿柔和 V 形图标（`chevron`）风格冲突，组件边缘割裂 |
| U7 | **单串口快捷指令栏** | 快捷指令以接收区与发送区之间的下拉横条呈现，收起按钮位于发送框右下角；设备串口服务提示另占一行 | 目前支持选择后填入或发送，但不便浏览整组指令；折叠横条和服务提示显隐会改变下方区域位置 |
| U8 | **文件页 / 远程页 / 设备页 / 底栏** | 1. 文件页“传输任务”空表默认展开，占高 `105~140px`，目标目录另占一行；<br>2. 远程页与设备页以单列排列，宽屏横向空间利用较少；<br>3. 活动消息缺少时间戳，任务状态展示可进一步汇总 | 可增加首屏文件行数、改善宽屏布局，并明确反馈时间与活动任务 |

### 1.2 功能与工作流短板（6 项）

| 编号 | 任务场景 | 现状短板 |
| --- | --- | --- |
| F1 | **长时间串口老化 / 启动抓包** | 普通日志最多 2000 条/512 KiB，终端最多 10000 行/1M 字符单元；现有导出保存当前视图，缺少独立于显示裁剪的持续录制 |
| F2 | **串口盯屏排查异常** | 缺少只读关键字高亮（如 `ERROR`、`FAIL`、`panic`、`Exception`），长日志流中肉眼定位错误困难 |
| F3 | **ADB 设备目录高频切换** | 每次需手动输入 `/data/local/tmp`、`/sdcard`、`/vendor/etc`、`/userdata` 等路径，无预置书签与收藏夹 |
| F4 | **ADB 文件管理闭环** | 只能上传/下载，推入二进制或整理日志时缺少新建目录、重命名、二次确认删除及赋予可执行权限（`chmod 755`） |
| F5 | **远程调试高频维护** | 远程调试页只有打开 Shell 和投屏，缺少 `logcat`/`dmesg` 导出、显式提权/挂载与重启入口 |
| F6 | **板卡硬件只读核验** | 三项原生只读能力、任务客户端与 Board Profile 评估器已有实现；界面仍需接入规格文件、任务生命周期及“读取结果/规格判定”的展示 |

## 2. UI 视觉、布局与交互重塑详细设计

### 2.1 顶部全局栏重塑（解决 U1、U2、U3）

#### 布局线框图

```text
┌─────────────────────────────────────────────────────────────────────────────────────────────────┐
│ TestTools 调试工作台  │  设备 [RK3562 · a1b2c3d4       ▾] [↻ 刷新]  │  ● ADB：已在线   ● 板端服务：未连接 [连接服务] │
└─────────────────────────────────────────────────────────────────────────────────────────────────┘
```

#### 具体设计规则

1. **三区结构**：
   - **左区（品牌区）**：`TestTools`（18px SemiBold）+ `调试工作台`（12px 次级灰）。
   - **中区（目标设备组）**：`设备` 标签 + `设备下拉框`（常用宽度 240~320px，窄屏允许收缩）+ **紧邻右侧的 `[↻ 刷新]` 按钮**。二者间距为 `6px`；长设备名称省略显示并提供完整提示，保留刷新和服务动作的空间。
   - **右区（双通道状态与服务动作组，靠右对齐）**：依次排列 `ADB 状态指示签`、`板端服务状态指示签`、`板端服务动作按钮`。
2. **服务命名与状态流转**：

| 服务状态 (`AgentServiceState`) | 顶栏状态指示签文本 (`topServiceStatus_`) | 顶栏动作按钮文本 (`topServiceButton_`) | 按钮点击行为 |
| --- | --- | --- | --- |
| `Disconnected`（无在线 ADB 设备） | `● 板端服务：未连接`（中性灰） | `连接服务`（禁用态） | 悬停提示：“请先连接并选择在线的 ADB 设备” |
| `Disconnected`（ADB 设备已在线） | `● 板端服务：未连接`（中性灰） | `连接服务`（可点击） | 自动执行检测、按需部署、端口转发与握手 |
| `Connecting` | `● 板端服务：正在启动…`（或显示具体步骤，暖黄） | `启动中…`（禁用态） | 防止重复触发 |
| `Ready` | `● 板端服务：已就绪`（成功色） | `服务详情`（次级按钮） | 跳转到“设备信息”页查看板端能力、断开或重置服务 |
| `Failed` | `● 板端服务：连接失败`（低饱和红 `#A34A42`） | `重试连接`（警示描边按钮） | 重新发起服务连接与准备流程 |

3. **区分状态标签与按钮**：
   - **状态标签**：无实体边框，使用透明或极浅底色、彩色状态圆点与文字；颜色复用 `UI_DESIGN.md` 的中性、警告、成功和错误语义。鼠标为普通箭头，同样规则应用到串口连接状态。
   - **可点击按钮**：具备明确的 `1px` 边框、圆角 `7px`、悬停变色反馈及手型光标（`Qt::PointingHandCursor`）。

### 2.2 按钮 3 级视觉体系与主操作重心恢复（解决 U4）

将 [`src/ui/theme.cpp`](../../src/ui/theme.cpp) 中相关样式归入 **3 个视觉角色**，颜色和尺寸沿用 `UI_DESIGN.md`。角色不要求对应固定数量的样式选择器；危险、禁用和进行中属于动作状态。

| 级别 | 样式标识参考 | 视觉表现 | 适用位置 |
| --- | --- | --- | --- |
| **一级：主动作按钮（Primary）** | `primaryButton` | 实心棕红底 `#AD694E`、白字 `font-weight: 600`、悬停 `#995B43` | 1. 串口未连接时的 **`[连接]`**（单串口/终端）与双端 **`[连接两端]`**；<br>2. 串口发送框右下角的 **`[发送]`**；<br>3. 文件窗格底部的 **`[上传所选]`** / **`[下载所选]`**；<br>4. 投屏面板未启动时的 **`[开始投屏]`**；<br>5. 设备信息页的 **`[连接板端服务]`**。 |
| **二级：常规操作按钮（Secondary）** | 默认 `QPushButton` / `secondaryButton` | 白底 `#FFFFFF`、描边 `#CFC9C2`、石墨字 `#302F2D`、悬停 `#F3F0ED` | 串口已连接后的 **`[断开]`**、**`[定时 / 次数…]`**、双端 **`[双向收发验证]`** / **`[可靠性压测…]`**、顶栏 **`[连接服务]`** / **`[服务详情]`**、远程调试页 **`[打开 ADB 终端 ↗]`** 等。 |
| **三级：工具栏轻量按钮（Ghost / Tool）** | `ghostButton` / `QToolButton` | 浅暖灰或透明底、柔和边界、12px 字号；常规点击目标至少 32×32 逻辑像素，目录导航保持 30×30 | 搜索、清零、保存、录制、高亮、刷新、更多参数与指令行内动作；“清空”保留可辨认的次级边框。 |

**动态主次切换**：未连接时突出 `[连接]`；连接后 `[断开]` 转为次级，普通调试的 `[发送]` 保持主动作。串口终端连接后以直接输入为主，不增加发送按钮。优先保留稳定的 `objectName`，通过样式属性切换角色并重新应用样式；始终分别核对启用、禁用、悬停和键盘焦点状态。

### 2.3 左侧导航栏容器与图标统一（解决 U6）

1. **绘制统一抗锯齿折叠图标**：在 [`src/ui/theme.cpp`](../../src/ui/theme.cpp) 中复用 `QPainter` 矢量绘制逻辑，生成向右（`▸`）与向下（`▾`）两枚抗锯齿柔和 V 形图标（颜色 `#67615C`，选中态 `#754837`），替代 `QToolButton::setArrowType(Qt::DownArrow / RightArrow)` 的粗糙三角形。
2. **一级导航组一体化容器**：将“串口调试 + 展开按钮”和“ADB 调试 + 展开按钮”分别包裹在带圆角的行容器（`QFrame#navigationGroupRow`）中；当处于选中或悬停状态时，整行（含右侧箭头区域）共同呈现统一的圆角背景色，消除“左边圆角块、右边箭头悬空”的割裂感。

#### 具体设计规则

1. **去除单串口与终端模式的双重外框**：
   - 在 `WorkspaceMode::Single` 与 `WorkspaceMode::Terminal` 下，隐藏 `channels_[1].group`（`endpointCard`）的边框、背景色与外围内边距（设为 `0`），使连接栏、接收框、发送框直接平铺对齐页面边缘；
   - 仅在 `WorkspaceMode::Dual`（双端调试）下保留左右两个 `endpointCard` 卡片边框以区分端点 A 与端点 B。
2. **板端服务未连接提示内联化（移除整行跳动的 `serialServiceHint`）**：
   - 将原先位于连接栏上方的 `serviceHint_` 调整为连接栏内的提示区域；
   - 选择“设备串口”且服务未就绪时，在原状态与连接动作位置显示 `需连接板端服务` 和 `[连接服务]`；连接中、失败和重试沿用相同位置。预留提示区域或复用原控件空间，避免服务状态变化挤动日志区域，并核对双端布局。
3. **快捷指令右侧可折叠侧边栏**：
   - 主工作区使用可调宽度的水平分隔：左侧为“收发记录 + 手动发送框”，右侧为 `shortcutSidebar`，建议初始宽度 `240px`。连接栏横跨工作区，侧栏不挤压连接参数。
   - 侧栏顶部为 `快捷指令`、指令库管理菜单和收起入口；收起后保留明确的展开按钮。展开偏好与宽度保存至 `serial-preferences.json`。
   - 首次使用时，宽度足够才默认展开。窄屏优先保留日志和发送区，允许折叠侧栏；临时适配不覆盖用户保存的展开偏好。接收工具条保留录制状态与停止入口，清零、导出、高亮等按空间移入“更多”菜单，避免把所有动作硬塞一行。
   - 指令列表项：每行显示指令名称、副标题预览（指令内容或 `[HEX]` 标记），右侧提供两个紧凑按钮 `[填入]` 与 `[发送]`，支持一键直接发送，无需先下拉选择再点发送。
   - 选择列表项只改变选择；`[发送]` 才真实发送，并复用当前端点、共享行尾、会话队列和错误处理。未连接、计划发送或资源冲突时沿用现有门禁。长名称与指令预览省略并提供完整提示。
   - 移除原先夹在接收框和发送框之间的横条以及发送框右下角的 `[收起快捷指令]` 按钮，发送框底部右侧只保留：`[清空]`、`[定时 / 次数…]`、主按钮 **`[发送]`**。

### 2.5 文件传输、远程调试、设备信息与底栏布局优化（解决 U8）

1. **文件传输页（`FileTransferWorkspace`）**：
   - **窗格底部紧凑化**：将 [`FilePane`](../../src/ui/widgets/file_pane.h) 的条目摘要、目标目录与上传/下载按钮优先放在同一行。长路径省略并提供完整提示；窄窗格允许目标目录另起一行，目标含义和主动作始终可见。
   - **底部传输任务区按需展开**：页面初始化尚未执行任何传输任务时，`records_` 传输记录列表默认收起（`taskToggle_` 处于未勾选态，仅显示单行状态栏）；当用户首次发起上传、下载或拖放任务时自动展开 `records_` 列表，最大化首屏双栏文件列表的可视行数。
2. **远程调试页（`buildMirrorPage`）左右双栏化**：
   - 将原先上下窄条堆叠改为左右并排的响应式双栏布局（`QHBoxLayout` / `QSplitter`）：
     - **左栏卡片（ADB 终端与设备维护）**：包含“ADB Shell 独立终端启动”、“诊断日志抓取（Logcat / dmesg）”与“设备维护控制（Root & Remount / 重启 / Loader 刷机模式）”。
     - **右栏卡片（Android 投屏控制）**：内嵌 [`ScreenMirrorPanel`](../../src/ui/screen_mirror_panel.h)，用布局分配空间替代整页固定的 `setMaximumWidth(700)` 限制。
   - 宽度足够时左右排列；两栏最小可用宽度无法同时满足时改为上下排列。调整布局只改变控件排列，保留正在运行的会话。
3. **设备信息页（`buildDeviceInfoPage`）双列卡片 + 板卡核验区**：
   - 顶部拆分为左右并排的两张卡片：
     - **左上卡（板端服务与连接维护）**：显示目标设备、服务状态、连接/断开/重置动作、版本兼容性与连接权限。
     - **右上卡（硬件与系统身份）**：采用紧凑双列网格展示板卡型号、厂商/产品、CPU/内存硬件资源、系统内核、构建版本与已声明能力标签。
   - **下部卡片（板卡只读硬件核验）**：展示系统可见内存容量、存储信息和健康字段，与规格配置分别呈现（详见 3.5 节）。两张顶部卡片在窄屏改为上下排列。
4. **底部全局活动栏（`activityBar`）**：
   - 每次调用 `MainWindow::setActivity` 时自动前置当前本地时间戳（格式 `[HH:mm:ss] 消息内容`），方便确认操作反馈的新鲜度。
   - 右侧汇总计划发送、压测、录制与文件传输的真实运行状态，同时活动时显示数量和可展开摘要；数据来自各用例快照，不根据最近一条活动消息推断。停止入口明确指向任务，防止“停止录制”被理解为断开串口。

## 3. 新增功能与工作流详细设计

### 3.1 串口实时流式录制（Session Recording，解决 F1）

- **目标与范围**：首版提供单文件持续录制，保存录制期间会话收到的数据，与普通日志和终端回看缓冲独立。完整性结论限定在会话已收到且录制器成功保存的数据，不据此推断硬件链路没有丢字节。
- **接入位置与所有权**：
  - 在无 Qt 的 [`SerialSession`](../../src/application/serial/serial_session.h) 内接入独立录制器，由录制器拥有后台写入线程、文件和统计。RX 在投递 GUI 前入录制队列；TX 在传输报告成功后记录，与界面是否显示 TX 无关。
  - 采集时保存会话代次、方向、时间和字节副本，顺序在录制器内确定。接收/发送回调只做有界入队，不执行文件打开、写入、flush 或等待写入线程。
  - 录制快照至少包含状态、格式、文件路径、开始/结束时间、已接受数据字节、已写文件字节、待写字节和错误原因。数据字节与包含前缀的文本文件字节分别统计。
- **格式**：
  - **带标记文本（`.log`，默认）**：以采集时间标注 RX/TX，按有界批次写入。UTF-8 使用跨批次增量解码；无换行的连续输出也要定期写出，不能为等待完整行无限积压。文本用于阅读，逐字节分析使用原始格式。
  - **原始 RX（`.bin`）**：只写 RX 字节，不混入 TX、时间戳或错误说明。同名元数据文件记录目标、串口参数、录制起止、字节统计及完成/失败原因，便于识别不完整片段。
- **写入队列与错误**：
  - 队列按数据字节限制，初始上限建议为 `4 MiB`，后续依据样本调整。达到上限时停止接收新的录制数据并报告“录制失败：写入积压”，后台尽量保存已接受记录；不能静默丢弃后仍显示完整，也不能无限增长或阻塞串口回调。
  - 写入按批次进行，周期性 flush；磁盘满、打开或写入失败均停止录制，保留已生成文件和原因，通过快照通知 UI。录制错误不关闭串口、不停止普通收发。
  - GUI 显示通道同样需要有界积压：阶段 1B 使用有界缓冲和合并通知，视图超限明确提示截断；录制始终位于显示裁剪之前。进一步自适应吞吐优化见阶段 4。
- **生命周期与界面**：
  - 用户选择路径后立即有界缓存新数据，后台打开成功后进入录制；准备期间展示状态，打开失败则明确报告未完成。覆盖已有文件需明确确认。入口显示 `停止录制`、状态和已写大小，窗口变窄时仍保留停止入口。
  - 切页、搜索、过滤、清空视图和显示缓冲裁剪不停止录制。同一会话在单/双模式间保留时继续录制；会隐藏活动端点的切换遵守现有模式门禁。
  - 停止或串口断开后先停止入队，再由后台排空、flush 并关闭文件；期间显示“正在保存”，完成或失败后才允许重用录制目标。退出等待所拥有的写入任务收敛，GUI 不同步等待刷盘。

### 3.2 串口接收区与终端只读关键字高亮（解决 F2）

- **目标**：辅助工程师在长日志流中快速捕捉异常关键字，不污染原始数据。
- **设计规则**：
  - 在接收区/终端标题栏提供 `[高亮]` 开关按钮（可勾选，状态记入偏好）。
  - 开启后，在渲染可见文本块或调用 `setExtraSelections` 时，对匹配规则的文本片段叠加柔和背景/前景色：
    - **错误级（浅红底 `#F7E9E8` + 深红字 `#A34A42`）**：匹配 `ERROR`、`FAIL`、`FAILED`、`panic`、`Exception`、`Segfault`，使用固定规则和一致的大小写策略。
    - **警告级（浅黄底 `#F6EFE2` + 深黄字 `#87652F`）**：匹配 `WARN`、`WARNING`、`timeout`。
  - 搜索命中优先于关键字高亮。实现使用增量文档高亮叠加在 ANSI/方向格式之上，搜索继续独占 `setExtraSelections`；两层不互相覆盖，关闭搜索后恢复关键字高亮。
  - 按新增/变化文本块增量匹配，滚动和截断后重算相关位置；避免每个接收批次复制并扫描整个终端历史。ANSI 原有样式保留，高亮作为显示叠加。
  - **严格只读**：不修改 `SerialLogBuffer` / `SerialTerminalBuffer` 存储的内容，不影响日志导出文件，也不触发任何串口发送。

### 3.3 ADB 文件传输：常用路径书签与受控文件操作（解决 F3、F4）

#### 1. 设备端常用目录与历史

- 在设备端 [`FilePane`](../../src/ui/widgets/file_pane.h) 的地址下拉框（`address_`）中，将下拉项分为两组：
  - **固定常用目录（置顶）**：公共路径为 `/`、`/proc`；Android 增加 `/sdcard/oem_log`、`/sdcard`、`/data/local/tmp`、`/vendor/etc`，Rockchip Linux 可增加 `/userdata`。系统类型未知时使用公共组；预置路径不表示该目录在当前设备必然存在。
  - **最近访问历史**：按设备序列号保留成功打开的目录，最多 20 条，重复路径去重。
- 选择下拉项触发打开；手工编辑地址仍按 Enter 或点击打开才提交。路径不存在或权限不足时保留原列表及错误，书签选择不修改正在传输批次的目标。

#### 2. 受控文件管理操作（新建目录 / 重命名 / 删除 / 修改权限）

- **接口与归属**：由 `FileTransferService` 协调固定操作，设备实现扩展 [`IFileTransferBackend`](../../src/core/device/file_transfer.h)，本地操作使用受控文件系统接口。Qt 只提交意图与显示结果；不增加任意命令入口，也不通过 Agent shell RPC 执行。

| 操作 | 固定语义 | 结果要求 |
| --- | --- | --- |
| `createDirectory` | 在已打开父目录下新建一个目录，同名项目存在则失败 | 显示实际目标和错误，不自动覆盖 |
| `renameEntry` | 同目录内重命名一个项目，目标同名则失败 | 首版不做隐式覆盖或跨目录移动 |
| `removeEntries` | 对明确选择的项目逐项删除 | 保留每项已完成/失败/取消结果，不用一个布尔值掩盖部分成功 |
| `setPermissions` | 设备端普通文件/文件夹通过弹窗修改自身权限，先读取实际值，勾选或输入八进制数 | 参数校验、非递归；多选不一致须明确指定，不默认套用 755 |

- **输入和目标校验**：
  - 文件名为单层名称，拒绝空值、`.`、`..`、分隔符、NUL 和控制字符；本地还要符合 Windows 文件名规则。路径与文件名由 application 和 adapter 分别检查，命令参数独立引用。
  - 沿用已成功打开的目录，启动时固定设备序列号、目标端、父目录和选择项；确认框也使用该快照。执行前复核目标，旧回调不能覆盖新设备界面。
  - 当前浏览允许目录链接，因此保护判断必须检查解析后的父目录与最终目标。拒绝删除根目录、挂载点本身，以及递归删除会包含受保护挂载点的目录；至少覆盖 `/system`、`/vendor`、`/proc`、`/sys`、`/dev`、`/sdcard` 本身，本地覆盖盘符根目录和共享根目录。
  - `/proc`、`/sys`、`/dev` 内保持只读。递归删除不跟随符号链接或 Windows 重解析点；删除选中的链接只删除链接本身，设置权限拒绝链接。无法可靠确认目标或挂载点时返回原因。
- **执行与交互**：
  - 删除前确认目标设备、完整父目录、名称和数量，并说明直接删除的影响。新建、重命名和设置权限由用户显式触发，权限不足直接报告。
  - 文件变更与现有传输共用互斥门禁，活动批次期间禁止新建、改名、删除或改权限。操作在后台执行，定义超时、取消及退出收敛；取消不回滚已完成项。
  - 操作后刷新涉及的已打开目录，保留筛选与位置；界面列出逐项结果，失败可针对原目标重试。固定 ADB 命令复用现有进程取消和参数引用机制。

### 3.4 远程调试页：ADB 诊断抓取与显式设备控制（解决 F5）

远程调试页保留外部 Shell 与投屏入口，增加两组固定动作。application 层负责目标、状态和门禁，adapter 层执行固定 ADB 命令，`MainWindow` 负责后台调度与展示。

| 动作 | 适用范围与执行 | 结果边界 |
| --- | --- | --- |
| 导出 Logcat 快照 | Android；`adb -s <serial> logcat -d` | 保存读取时可见的缓冲区，不表示全程日志或跨缓冲区的一致性快照 |
| 导出内核 dmesg | 支持该工具且当前身份有读取权限的设备；`adb -s <serial> shell dmesg` | 权限不足报告当前限制；现有板端服务没有 dmesg 能力，连接它不会提升 ADB Shell 权限 |
| 切换 Root 并尝试挂载可写 | Android 调试系统；确认后执行 `root`，在有界时间内确认原设备恢复在线并核验身份，再执行 `remount` | 分别记录提权和挂载结果，支持部分完成；不把命令已返回当作所有目标分区可写 |
| 重启设备 | 确认后执行 `adb -s <serial> reboot` | 命令已发出、设备离线、重新上线分别显示，上线不等于系统启动验收通过 |
| 重启至 Loader | 仅对已有板型/BSP 依据确认支持的 Rockchip 设备开放；确认后执行 `adb -s <serial> reboot loader` | 命令成功或 ADB 离线不证明已进入 Loader；是否进入需由实际 USB 枚举或实机观察确认 |

- 日志导出由用户选择路径后后台执行，不再增加设备操作确认；覆盖本地文件仍需明确确认。输出流式写文件，避免完整日志进入 GUI 或通用命令输出缓冲。超时、取消、磁盘错误时保留并标明部分文件，不能显示导出成功。
- 维护动作确认框固定原设备和动作，执行期间不自动改用另一台在线设备。与同设备上的文件任务、设备串口、板级任务及投屏冲突时，要求先结束相关任务；Windows 本地 COM 独立工作。
- `root` 可能重启 adbd，准备、等待、失败和超时都要可见，连接状态与转发按现有代次机制重新确认。`remount` 可能受构建类型、verity 或 OverlayFS 限制；首版报告实际结果和下一步，不自动追加关闭校验或重启操作。依据见 [AOSP remount 说明](https://android.googlesource.com/platform/system/core/+/refs/heads/android16-release/fs_mgr/README.overlayfs.md)。
- 每项操作定义超时与取消，关闭窗口只收敛本工具拥有的任务和进程，不重启共享 ADB server。对已经发出的重启无法撤销，取消等待也不能显示为设备动作已取消。

### 3.5 设备信息页：启用板卡只读硬件核验（解决 F6）

- **已有基础**：复用 [`BoardTestJobClient`](../../src/application/agent/board_test_job_client.h)、[`Profile` 加载与评估器](../../src/application/agent/board_profile.h) 和 Agent 原生只读能力；这些实现已有契约测试，当前 GUI 工作流与新设备兼容性仍需本阶段验证。
- **页面与观察值**：下部卡片标注“只读 `/proc`、`/sys`，按已加载规格核对”。分别展示：

| 能力 | 界面名称与实际含义 | 判定注意事项 |
| --- | --- | --- |
| `memory.capacity` | 系统可见内存容量，读取 `/proc/meminfo` 的 `MemTotal` | 与该板型/BSP 配置的 MemTotal 范围比较；不能直接按 DDR 标称容量判定 |
| `storage.device.info` | eMMC/UFS 类型与设备容量 | 展示所有候选设备；没有唯一符合规格的对象时待核对，不随意挑选主存储 |
| `storage.device.health` | eMMC/UFS pre-EOL、寿命字段与可读取的 I/O 计数 | 保留设备报告的值及单位/含义，缺失保持未知，不填 0 或推算剩余寿命百分比 |

- **规格配置**：沿用 [ADR-0003](0003-stable-board-capabilities-and-providers.md) 的只读 Board Profile 模型，首版从程序目录 `profiles/boards/` 加载随版本管理的 JSON。将实际发布、加载路径和可追溯的板型规格一并接入，界面展示加载错误、配置 ID/版本与匹配结果；缺少配置时仍可读取观察值。
- **判定**：调用现有唯一身份匹配与逐项评估，零匹配、多匹配、缺少必需期望或观察值均显示“待核对”。只有唯一规格及完整证据才判定“通过/不合格”，不从本次实测值反推合格范围。规则与字段来源沿用协议和评估器，不另写 GUI 阈值判断。
- **执行生命周期**：仅启用当前 Agent 声明的能力；单项或“一键核验”均按全局单板级任务约束顺序执行，支持轮询、超时、取消和断线收敛。保存设备/会话代次，旧结果不混入新设备；下一项启动前保留前一项终态结果。
- **结果表**：分开展示“未执行/运行中/读取完成/执行失败/已取消/超时”和“通过/不合格/待核对”，附观察值、预期范围、原因及 Profile ID/版本。任务执行成功不直接显示规格通过。

| **2B：诊断与维护** | 远程页响应式布局、日志导出、显式提权/挂载与重启入口 | 独立 application 用例及 ADB 适配器、远程页；建立 `docs/features/DEVICE_MAINTENANCE.md`，同步架构中固定主机动作的范围 | 流式导出及部分文件、权限错误、任务门禁、固定设备、提权/挂载部分完成和超时；Loader 仅开放已确认支持的目标 |
| **3：板卡只读核验** | 设备信息响应式卡片、Profile 加载、三项顺序任务与分层结果 | `application/agent`、设备页与配置打包；建立 `docs/features/BOARD_CHECKS.md`，同步 `PRODUCT.md`、`UI_DESIGN.md` | 连接/失联状态、零/唯一/多规格匹配、字段缺失、执行失败/取消/超时；读取完成与规格判定分别正确显示 |
| **4：按需整理与性能** | 拆分仍复杂的协调逻辑，按实测调整接收批次 | 对应 application/UI 模块；职责变化同步 `ARCHITECTURE.md`，行为变化同步功能契约 | 相关回归通过；按实际样本记录响应和积压，拆分保持原有资源、代次和退出语义 |

各批次的实现与验证结果均更新 `STATUS.md`。新增契约文件在对应功能实施时创建，拟议功能完成后再记录实现和验收结果。落地后，本 ADR 保留取舍与链接，稳定行为规则归入相应功能契约。

## 6. 实施约束与验证方法

开发边界继续遵循 [`AGENTS.md`](../../AGENTS.md) 和 [`DEVELOPMENT.md`](../DEVELOPMENT.md)。以下仅列出与本轮改动直接相关的依赖和验收方式。

### 6.1 界面测试与行为同步

[`tests/ui/`](../../tests/ui/) 的部分测试使用 `#define private public` 访问成员，并检查文案、可见性和发送字节。成员或布局调整时同步更新行为断言：

| 测试 | 关注内容 |
| --- | --- |
| [`service-icons-smoke.cpp`](../../tests/ui/service-icons-smoke.cpp) | 顶栏服务文案、失败/重试、内联提示与服务连接入口；保留本地 COM 独立工作路径 |
| [`iteration-smoke.cpp`](../../tests/ui/iteration-smoke.cpp) | 服务详情入口、独立页面与偏好、端口占用交接、万行增量显示 |
| [`serial-smoke.cpp`](../../tests/ui/serial-smoke.cpp) | 快捷指令填入/发送/折叠、共享行尾、连接/断开与精确发送字节 |

测试应随新组件结构访问正确入口；移除的控件不必仅为旧成员名保留。验证操作含义和结果，不能只把旧文案断言替换为新文案。

### 6.2 文件后端接口与假实现

扩展 [`IFileTransferBackend`](../../src/core/device/file_transfer.h) 时，同步检查 [`tests/file_transfer_tests.cpp`](../../tests/file_transfer_tests.cpp)、[`ui-smoke.cpp`](../../tests/ui/ui-smoke.cpp) 和 [`iteration-smoke.cpp`](../../tests/ui/iteration-smoke.cpp) 中的假实现。新增方法同时约定取消与结果，更新真实适配器和假实现。可选能力若返回“不支持”，UI 也应有对应状态；默认失败实现不能充当新增操作的验证。

### 6.3 无 Qt 边界与静态扫描

[`check-baseline.ps1`](../../scripts/check-baseline.ps1) 对非 UI 目录执行文本扫描，当前匹配 Qt include 及 `QString`、`QByteArray`、`QObject`，注释也会命中。它没有穷尽所有 Qt 类型，架构约束仍是 core/application/adapters/Agent 不依赖 Qt。中文注释说明职责、代次、队列和错误边界，避免写与所属层无关的控件实现。

### 6.4 项目登记与对象文件依赖

- 新增桌面源码登记到 [`TestTools.vcxproj`](../../TestTools.vcxproj) 和 [工程筛选器](../../TestTools.vcxproj.filters)；无 Qt 测试按实际目标依赖更新 [`tests/CMakeLists.txt`](../../tests/CMakeLists.txt)，不把平台适配器无差别加入所有测试。
- [`tests/ui/CMakeLists.txt`](../../tests/ui/CMakeLists.txt) 直接链接产品的 Release `.obj`。产品源码变化后先重建 Release，再配置、构建 UI 测试；新增/移除 `.cpp` 必须重新配置，因为当前 `file(GLOB HOST_OBJECTS ...)` 未启用 `CONFIGURE_DEPENDS`。
- 文件删除或改名后复核对象列表；生成目录中遗留的旧 `.obj` 也可能被通配符拾取，需要定向清理或重建相关产物。旧对象与旧测试结果不能用于本批验收。
- 本轮复用现有板端能力，桌面变更不联动递增 Agent 版本；若实施中确需修改 Agent，另按开发手册递增其版本并重建固定矩阵。

### 6.5 检查命令与适用范围

仅修改文档时运行静态入口即可，不触发桌面构建或设备操作：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\check-baseline.ps1
if ($LASTEXITCODE -ne 0) { throw '静态检查失败' }
```

代码批次交付时先构建产品并执行无 Qt 契约检查；UI 或其依赖变化时继续执行 UI 检查。首次配置 UI 测试的 Qt 前缀按开发手册设置，下列重新配置沿用已有缓存：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\check-baseline.ps1 -Build -Configuration All
if ($LASTEXITCODE -ne 0) { throw '构建或核心检查失败' }

cmake -S tests/ui -B build/tests/ui
if ($LASTEXITCODE -ne 0) { throw 'UI 测试配置失败' }
cmake --build build/tests/ui --config Release
if ($LASTEXITCODE -ne 0) { throw 'UI 测试构建失败' }
ctest --test-dir build/tests/ui -C Release --output-on-failure
if ($LASTEXITCODE -ne 0) { throw 'UI 测试失败' }
```

静态入口包含文档入口/相对链接、差异格式和分层检查。结束前复核 `git status` 与差异范围，保留原有无关改动；提交、标签与推送单独处理。

### 6.6 验收记录

- 快照与回归范围按 [开发手册第 5.2 节](../DEVELOPMENT.md#52-按改动选择快照与回归) 选择，目标适配质量遵循界面设计；不固定张数，也不默认展开页面 × 尺寸 × DPR × 状态。元数据检查、实际目检样本与交互结果分别记录。
- 阶段 1B 优先验证录制字节、停止/断线、写入错误和积压边界。界面代表样本选录制中、失败提示、高亮/搜索叠加及拥挤布局，再按改动补宽屏或高 DPI，通常约 4–6 张，可按实际需要增减；双端共用控件受影响时补查双端。
- 核心逻辑优先验证精确数据与关键失败边界；复用现有 CTest 和夹具，不为每个视觉调整新增核心测试或通用测试框架。
- 构建、静态、夹具、实机、异常、回归和压力结果分别写入 `STATUS.md`，未执行项明确写“未验证”。假 ADB、模拟磁盘错误和回环 Agent 只证明对应夹具路径。
- 实机按本批功能选择目标与操作范围，真实发送、文件写入和维护动作与只读检查分别记录；设备断开、重启启动日志、长时高波特率和 Loader 状态需要各自证据，不由编译或命令返回值替代。
