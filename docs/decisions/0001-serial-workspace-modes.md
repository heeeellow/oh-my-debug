# ADR-0001：串口工作台按连接拓扑提供两种调试方式

[返回串口功能契约](../features/SERIAL.md)

- 状态：已接受
- 日期：2026-08-30

## 背景

现有串口页默认并排展示两个端点，并同时暴露双向验证、可靠性压测和普通发送。该结构能覆盖高级
能力，但让最常见的单端调试承担了不必要的认知成本。

## 决策

串口工作台采用“单串口调试、双端调试”两种显式方式，默认进入单串口调试。双向收发验证和可靠性
压测都依赖端点 A/B，因此作为双端调试中的按需子功能；可靠性压测仍保持独立参数、运行状态和结果。

通用串口语义保持稳定，行尾由用户直接选择，自动发现不改变端口选择或发送语义。普通定时/次数
发送继续属于交互调试，不与可靠性压测共享任务状态和结果模型。

## 影响

- 初次使用路径更短，高级功能仍可发现但不长期占据主界面。
- 两种调试方式必须映射到明确状态，不能仅靠隐藏控件拼出不同流程。
- 双端调试统一承接链路相关能力，避免为共享同一端点配置的测试再复制顶层入口。
- 当前 `SerialWorkspace` 需要逐步拆分视图和应用状态，避免继续扩大单个 Qt 类。
- 需要增加方式切换、状态保留、四种行尾和异常断开的回归测试。

未采用“保持双端页面，仅调整颜色和间距”，因为它不能解决任务模型混杂。
