# ADR-0008：公司主板 GPIO 接口兼容方案

[返回当前状态](../STATUS.md) · [工具箱契约](../features/TOOLBOX.md) · [总体架构](../ARCHITECTURE.md) · [设备协议](../AGENT_PROTOCOL_V1.md)

- 日期：2026-11-05。
- 状态：已实施公司接口识别、读取和设置。当前实现、验证与交付以 [STATUS](../STATUS.md) 为准。
- 第 1–7 节保留实施前的设计与目标，不替代当前行为；已实现行为唯一依据为[工具箱契约](../features/TOOLBOX.md)和[协议](../AGENT_PROTOCOL_V1.md)。
- 范围：公司现有接口的发现、读取和设置；解绑、强制解除占用和新增驱动接管接口均不纳入实施。

## 1. 建议取舍

在现有 GPIO 页面增加“板载 GPIO”来源，优先复用公司驱动提供的控制接口，让已被该驱动申请的引脚也能通过其公开接口操作。
原通用 GPIO 字符设备方式继续保留。界面分别显示“谁在占用”和“有哪些控制方式”，不能再把两者合成一个可用/不可用判断。

实施分为只读识别与已知公司接口控制两步。原生接口仍拒绝申请已占用行，公司接口保持其驱动绑定和占用状态。

## 2. 初次只读实机证据

通过已有 USB ADB 读取两块在线主板，沿用设备现有权限，没有执行 Root/Remount、部署、重启或修改节点权限。

| 主板/设备 | 实际接口 | 驱动身份 | 观察结果 |
| --- | --- | --- | --- |
| MTB-720 / `66c8c84745c4330`，4.19.193+ | `/sys/class/rock_gpio/{gpio1…gpio10,sim_det}/value` | platform `rocktech_gpio`，设备树 compatible `fsl,rocktech_gpio` | 11 个 value 均读到 `1`；class 链接落在 `/sys/devices/virtual/rock_gpio/` |
| RTD-XL01 / `ac7f17a16344038`，5.10.157+ | `/sys/class/rock_gpio/otg_drv_vbus/value` | 同名驱动/compatible，platform 设备名为 `otg-vbus-gpio` | value 读到 `0`；这是 USB VBUS 用途，方案中默认只读 |

这些 `value` 的文件模式允许写入，但本轮**没有验证 store 实现、写入枚举、方向切换、恢复行为或真实电压**。
class 子节点为 virtual device，没有可直接追溯到 platform 驱动的 `device/driver` 链接；不能仅凭目录位置断定归属。
本轮通过 platform 设备的 uevent、设备树子节点 label/gpios、GPIO 控制器 phandle 与 debugfs 占用交叉核对映射。

MTB-720 的已核对映射如下；公司别名 `gpio1` 不是 bank 1，也不是 Linux GPIO 1。

| 公司别名 | Rockchip 管脚 | Linux 全局号 |
| --- | --- | --- |
| gpio1 / gpio2 / gpio3 | GPIO3_B5 / GPIO3_B6 / GPIO3_B7 | 109 / 110 / 111 |
| gpio4 | GPIO3_C1 | 113 |
| gpio5 / gpio6 / gpio7 / gpio8 | GPIO2_D0 / GPIO2_D1 / GPIO2_D2 / GPIO2_D3 | 88 / 89 / 90 / 91 |
| gpio9 / gpio10 | GPIO3_C2 / GPIO3_C3 | 114 / 115 |
| sim_det | GPIO0_C6 | 22 |

RTD-XL01 的 `otg_drv_vbus` 对应 GPIO2_A0 / Linux GPIO 64。两块板的这些管脚均出现在 debugfs 的已申请行中。
上述映射只适用于本次固件，不能写成所有同型号主板的固定编号。

MTB-720 子节点的 gpios flags 均为 `1`（标准绑定含义为 active-low），但当前 debugfs 未为这些行标出 ACTIVE LOW，
且 value=`1` 与 debugfs `out hi` 同时出现。这不足以判定驱动是否采用逻辑极性或原始电平，后续必须核对驱动 show/store；不能只按设备树 flags 自动翻转公司接口的值。

证据保存在本地忽略目录 `build/gpio-ownership-plan-20261105/`：每台设备的 `*-discovery.txt`、
`*-metadata.txt`、`*-readonly-values-dt.txt`、`*-controller-identity.txt`。设备时间戳不作为验证时间依据。

## 3. 范围与工作量评估

基于现有 Agent、任务协议和 GPIO 页结构，整体属于**中等偏低难度的小迭代**。底层读写公司 value 属性较简单，
主要工作在于确认接口语义，以及将新来源接入列表、能力判断、参数校验和结果展示。可复用现有连接、后台执行、确认及报告，不需要重做工具箱。

| 工作 | 预计难度 | 说明 |
| --- | --- | --- |
| 发现、读取和设置已知 value 节点 | 较低 | 两块板已发现相同的“子目录/value”格式；写入枚举和极性仍需驱动依据 |
| 同一接口使用不同目录或别名 | 较低 | 增加受限路径规则，复用同一适配；不能靠模糊目录名识别写入语义 |
| 公司别名关联实际 GPIO、统一列表及控制状态 | 中等 | 区分驱动占用和接口可控；复用已有编号换算，按当前设备身份关联 |
| 权限、断线、驱动/节点变化及重复操作验证 | 中等 | 扩展已有固定能力、实例和操作票据规则，覆盖写后读回失败等路径 |
| 属性格式或方向/极性语义不同的公司驱动 | 逐个评估 | 新增对应适配，不承诺一个目录规则覆盖全部固件 |

首版建议集中于已发现的 rocktech_gpio 格式，完成枚举、读取、已确认端点的 0/1 设置及写后读回。
公司接口的输入方向、脉冲和监听不自动继承字符设备能力；没有相应协议时不开放。

### 占用处理保持清晰

本工具原有任务继续通过停止/关闭所属句柄结束；外部程序和内核驱动占用继续显示，不提供解除入口。
公司驱动公开的接口经过适配后可操作，同时保留“驱动占用”的事实。没有公开接口的已占用行保持不可控。
不增加 unexport、unbind/bind、卸载模块、寄存器强写或 pinmux 改写能力，也不修改 BSP 驱动。
引脚复用仍要核对：行信息未显示已申请，并不证明该管脚当前没有被 UART/I²C 等外设功能使用。

## 4. 公司接口怎样兼容不同目录

采用 Agent 内的板载接口适配，目录名只用于定位，驱动协议才决定能力。首个候选适配为本次发现的 `rocktech_gpio`。
适配描述需要包含：

- 匹配身份：compatible、驱动及接口特征，必要时加固件/板型约束；不能仅匹配商品名或 class 名。
- 发现规则：受限的 class 根目录/已知别名、platform 设备及其设备树关联；同驱动不同设备名应能识别。
- 节点模式：子目录加 value、父目录中的命名属性等由各适配明确声明；目录或属性不同可以新增适配，不靠名称包含 gpio 就开放写入。
- 读写语义：合法值、换行格式、show 是否读硬件、store 是否改变方向、是否有异步业务写入、逻辑/物理极性及恢复办法。
- 能力和用途：只读、设置值、方向、通知/轮询等分别声明；实际管脚映射、影响范围和用途独立记录。

发现先枚举有界的 class 元数据和已匹配设备树，不递归扫描整个 sysfs，不读取所有未知属性。
未知目录或协议只展示“待适配”；没有 BSP 依据时不能通过试写 `0/1` 猜测协议。
扩展路径由受信任的适配描述提供，不把任意路径编辑器、任意 shell 或任意属性写入作为兼容方案。
标准 `/sys/class/gpio` 的 export 接口与公司自定义 sysfs ABI 分开处理，通用 GPIO 仍优先字符设备。

### 身份与冲突

同一物理行可有多个访问入口：保留一份物理行身份，在其下关联板载别名和可用操作。
用控制器真实设备/设备树 phandle、`#gpio-cells`、行偏移和适配的 binding 规则确认关联；consumer 同名只作为线索。
映射不唯一时显示未知，不按别名序号计算真实管脚，也不自动放宽该行的字符设备占用限制。

工具内部用物理行及必要的整组设备资源互斥，映射缺失则锁定整个适配设备并限制写入范围。
这只能约束本工具，不能阻止其他程序写同一 sysfs 节点或驱动自身异步更新；需要独占保证的操作必须有驱动侧协作。

## 5. 页面与操作语义

沿用 GPIO 页面和可选常用备注，增加“全部 / 通用 GPIO / 板载 GPIO”筛选及别名搜索。
选中行显示公司别名、真实管脚、接口来源、占用者、可用操作；技术路径收入详情。
例如 `gpio1 · GPIO3_B5 · Linux 109`，状态为“rocktech_gpio 占用，可通过板载接口控制”。
不同目录无需用户每次手工输入；刷新只读发现，不能自动试写。

| 接口能力 | 页面行为 |
| --- | --- |
| 原字符设备 | 保留现有读取、定时保持、脉冲、输入监听及释放语义 |
| 只读公司接口 | 展示原始值与已确认含义；无法确认时写明“极性未知”，不显示推测的高低电平 |
| 已验证的公司 value 接口 | 首期提供读取和明确的“设置值”；仅极性已确认时提供物理高/低，否则不开放高低电平控制 |
| 无方向/事件协议 | 不提供切输入或内核边沿监听；若以后加入轮询，单列为采样并说明可能漏掉短脉冲 |

公司接口的设置可能在关闭文件或退出工具后持续生效，不能复用“释放句柄”来暗示恢复。
首期将“设置值”作为一次明确写入，确认中说明是否持续生效，结果记录设置前值、目标值、写入结果与读回含义；不承诺自动恢复。
公司接口的脉冲和定时恢复不在首版范围；现有 5 秒租约也不能当成公司 GPIO 的硬件恢复机制。

`sim_det` 名称不能证明它是输入，本次 debugfs 实际为输出；`gpio1` 等通用名也不能证明外部接线可写。
首期识别到的节点均先只读，完成驱动语义和用途核对后按端点开放写入；VBUS、电源或复位用途不作为随意试写对象。

## 6. 工程与协议边界

- 无 Qt 核心层定义接口来源、端点身份、能力、值语义及结果；应用层负责后台发现、任务和快照，UI 只表现状态。
- Agent 原生读取设备树/元数据和固定 sysfs 属性，不通过 ADB Shell 执行业务。原有 `gpio.pin.*` 参数和语义保持。
- 候选新增 `gpio.board.list` 元数据方法，以及 `gpio.board.read` / `gpio.board.set` 固定能力；后两者沿用 `job.start`、prepare/abort、实例/所有者/操作标识和单板任务限制。
- 请求仅接受本实例签发的端点 ID、适配身份和严格枚举值，不接受用户传来的 sysfs 路径；端点过期、重新连接、驱动重绑定或身份不符时要求重新发现。
- 能力单独公告并检查版本，旧 Agent 明确显示“不支持板载接口”；不能只因协议仍为 1 就向旧 Agent 发送新请求。
- class 链接可以合法指向 virtual device，按适配验证最终目录、节点及关联身份；打开/操作时复核，拒绝路径替换、越界目标、未知字段、超长/非法值和不完整写入。
- 枚举、属性读取、结果和等待均有上限；权限/SELinux 错误按原样报告，不自动 chmod、Root 或换路径绕过。
- 写入响应丢失时先复核原操作，不重试新写入；报告区分“未写入 / 已写入 / 读回失败 / 结果未知”。读回成功不等于测到了外部电压。
- 服务实例变化不能把旧进程退出当成公司 GPIO 已恢复；重新发现/读值只确认当前状态，不把旧写入或恢复补记为成功。
- 元数据、报告及资源归属要携带来源、适配版本、原始值语义和可确认的物理行；驱动占用信息持续保留，不能将兼容控制伪装成空闲。

## 8. BSP 接口依据

核对的 BSP 包含 `kernel/drivers/mfd/rk-gpio.c` 和同目录提供 class 接口的 `rock-gpios.c`。
只读核对的源码基线为 `f0aede3148ac298cd2ee61411a0f7fa7029f5334`，文件摘要保存在
`build/gpio-board-0.18.0/evidence/bsp-source-context.json`；没有修改或编译服务器内核。
同格式的 gpio-control 变体另参考本地原始 `gpio-rocktech.c`，摘要也保存在该证据中；该变体未做实机验证。

- 两者 show 均使用 legacy `gpio_get_value` 读物理数字状态，store 写 `0` 切输入、`10` 输出低、`11` 输出高；写 `1` 不是有效的输出命令。
- class 驱动用 label 命名子节点；另一类驱动在 platform 设备中创建 gpio0…gpio5，分别对应设备树 gpio1…gpio6。
- 两类 store 均返回输入字节数，没有向用户空间传回 GPIO 配置函数的错误，所以设置需另读电平和方向核对。
- 初始 flags 用于驱动初始化，不能反推 show/store 值要按 active-low 取反。工具端点按固定驱动/compatible/布局识别，不继承未知固件的其他协议。

其他目录变体、方向/通知协议和命名用途仍需逐适配核实；源码阅读和软件模拟不代表全部固件或真实外部电压已验证。

## 9. 技术依据

- [Linux GPIO 字符设备申请与独占语义](https://docs.kernel.org/userspace-api/gpio/gpio-v2-get-line-ioctl.html)：已用行申请返回 EBUSY，关闭请求句柄后状态不再由用户空间保证。
- [Linux GPIO sysfs 文档](https://cdn.kernel.org/doc/html/latest/userspace-api/gpio/sysfs.html)：export/unexport 与内核主动导出不同；这份标准 ABI 不定义公司的自定义 class。
- [Linux 4.19 GPIO 设备树 flags](https://github.com/torvalds/linux/blob/v4.19/include/dt-bindings/gpio/gpio.h)：标准 active-low 位定义；不证明公司驱动实际采用该语义。
